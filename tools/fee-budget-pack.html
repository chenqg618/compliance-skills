费用与预算技能包（免费版）

完全本地运行：引擎已经打包在本技能里（scripts/engine/）。 核对过程不需要联网、不需要 API Key、没有调用次数上限、不写任何文件。

什么时候用

谁会在什么时候用：企业财务、管理会计、费用岗、代账公司在每月费用入账与经营分析会之前。

费用底稿从来不是一张表：预提费用与到票冲销、费用预算执行差异、部门费用预算执行、报销单合规预检、

租金账单与押金结算、物流仓储与操作费、设备维保与备件领用、承运司机运费结算、运费对账、

车队油耗与运费、物业费与滞纳金、物业公共能耗分摊、物业公共收益公示与分成、长期待摊费用摊销 ——

每一张都有自己的勾稽关系，逐张手核既慢又容易漏。

这个包做的事只有一件：--input <客户目录>（每个子目录 = 一个客户 / 一套材料），

一次跑完所有客户，每个客户一行结论。

下面 14 项，每个客户都跑一遍（检查项名字与引擎 CHECKS_GIVEN 逐条一致）：

  1. 预提费用与到票冲销核对
  2. 费用预算执行差异核对
  3. 部门费用预算执行核对
  4. 报销单合规预检
  5. 租金账单与押金结算核对
  6. 物流仓储与操作费核对
  7. 设备维保与备件领用费用核对
  8. 承运司机运费结算核对
  9. 运费对账
  10. 车队油耗与运费核对
  11. 物业费与滞纳金核对
  12. 物业公共能耗分摊核对
  13. 物业公共收益公示与分成核对
  14. 长期待摊费用摊销核对

引擎里的 CHECKS_WITHHELD（本免费版不执行的项）会逐条打印出来 ——

「跨客户汇总台账」「跨客户风险排序处理清单」「跨客户共性问题归类」「费用台账导出」——

它们是"未执行的检查项"的说明文本，不是实现。

另外，每个成员检查包自己没做的子检查（SUB_CHECKS_WITHHELD，本包合计 70 项）也在结果里

scope.sub_checks_not_run 如实列出 —— 两个档位都没实现它们，不会因为「买了完整档」就让买家以为这些项被跑了。

怎么用

node scripts/run.mjs --sample                  # 单客户样例（内置）
node scripts/run.mjs --sample-batch            # 3 个客户的批量样例（干净 / 有硬伤 / 没交材料）
node scripts/run.mjs --input 客户目录            # 批量：每个子目录 = 一个客户
node scripts/run.mjs --input 客户目录 --json     # 机器可读

客户目录怎么放（每个子目录里放该客户的一套费用与预算材料，每项用 === 检查项 === 分段，Tab 分隔最稳）：

客户目录/
  豫州商贸有限公司/费用与预算材料.txt
  中岳建材有限公司/费用与预算材料.txt

也可以把 14 张表拆成 14 个文件放进同一个子目录 —— 引擎会自己认表头找对应的那一项。

templates/sample.json 是引擎自己的样例，可以直接 --input 它先跑通一遍。

退出码：0 已执行检查 / 1 缺少入参 / 3 材料不足 / 4 入参读不到或无法解析 / 9 未预期错误。

材料不足（一个客户的材料都没有、材料为空或只有几行、认不出任何一张表）时，

本工具不做任何认定、也不给任何结论，打印缺什么并以退出码 3 结束 —— 不会把"没查"说成"通过"。

结论怎么读

  • 每个客户一行：[结论] 客户名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行；
  • 有价值的是问题明细：每条都带 客户 + 检查项 + 来源文件:行号 + 类别 + 具体数字，

第三方可以拿同一份材料复算；

  • 报销单合规预检那一项，它的样例本身就是一份同一张发票号出现两次的报销底稿，

所以 --sample 会照实报出这 1 条 P0（这是该项的真实结论，不是误报）；其余 13 项在各自样例上是 0 条发现。

使用次数与完整档

本免费版每次运行结束后会向服务端做一次匿名次数统计：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），不发送你的材料、不写任何文件。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；

· 第 4 次起：服务端会返回一段完整档说明（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；

· 统计不可用（离线/超时/被拦截）时什么都不做，核对结果与退出码不受任何影响。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

常见错法

  • 把 14 项的材料全塞进一个文件却不分段：引擎按 === 检查项 === 分段找每一项的表；

不分段时只有第一段能被认出，其余 13 项会如实标成「未执行」并报一条「材料只覆盖了一部分」，

不是"查过了没问题"。

  • 一个客户一个目录：--input 指向的目录里，每个子目录 = 一个客户。

把所有客户的表放进同一个子目录，会被当成一个客户，跨客户的差异与汇总也就无从谈起。

  • 以为「未执行」=「通过」：某客户只交了 3 张表，那 3 项之外的 11 项是没有核，

结论里写的是「未执行」，并且会单独报一条覆盖缺口。

  • 表头行被删掉：只贴数据行不贴表头，该项直接变成「未执行」（引擎认不出列的角色）。
  • 把"运费对账"和"车队油耗与运费"两张表合成一张：它们都含"运费"字样，合成一张会让两张表

各认一段、结论挂错检查项；一张表一个 === 检查项 === 段，或者一个文件一张表。

  • 拿 --sample 的输出当自己的结论：样例只是让你确认「跑得通、格式对」，

真正的结论必须来自你自己的材料。
