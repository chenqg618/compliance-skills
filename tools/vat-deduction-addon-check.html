增值税加计抵减核对（免费版）

完全本地运行：引擎已经打包在本技能里（engine/ 目录）。 核对过程不需要联网、不需要 API Key、没有调用次数上限。

什么时候用

谁会在什么时候用：适用增值税加计抵减政策的一般纳税人（生产、生活性服务业等），

在每月申报增值税、填写加计抵减台账之前，必须把台账逐期滚动核一遍：

  • 本期计提加计抵减额 = 当期可抵扣进项税额 × 加计抵减比例；
  • 期末加计抵减余额 = 期初余额 + 本期计提 − 本期调减 − 本期实际抵减；
  • 本期实际抵减 ≤ 抵减前应纳税额（抵减不能超过当期应纳税额）；期末余额 ≥ 0。

台账这几列一旦滚不上，申报表附表也会跟着错；而这类错误全都能算出来对错。

这个免费版查什么

  1. 合计行逐列复核：销售额 / 四项服务销售额 / 进项税额 / 计提 / 调减 / 实际抵减（余额列不相加）；
  2. 期末余额 = 期初 + 本期计提 − 本期调减 − 本期实际抵减（滚动关系，最常错的一条）；
  3. 本期实际抵减 ≤ 抵减前应纳税额；
  4. 期末余额为负检测；
  5. 同一所属期重复行检测；
  6. 空白与占位符检测（含必需列缺失）。

常见错法（这张台账里真的会有人这么填）

  1. 把"期初余额"当成上月计提额：期初余额是上期期末结转的可用额度，不是上月计提数；填错会让整条滚动关系断掉。
  2. 本期调减额留空却实际发生了调减（进项转出、红冲时要做调减）：留空等于默认 0，会算出偏大的期末余额。
  3. 实际抵减填成"计提额"：实际抵减受当期应纳税额限制，两者通常不等；相等往往说明没做限额判断。
  4. 比例写成整数 10（而不是 10%）：本工具两种写法都认（10 = 10%），但12%这种非政策档位会被点出来核对政策依据。
  5. 同一所属期分两次粘贴（补录时重复）：会报重复行；如确实分两笔，请合并成一行或注明凭证号。

需要完整档时（可选）

本免费版是完整可用的核心产出，本版本不包含下面这些项：

  • 本期计提 = 当期可抵扣进项税额 × 加计抵减比例 复算
  • 四项服务销售额占比低于 50% 却计提加计抵减（资格存疑）提示
  • 本期实际抵减超过可用额度（期初 + 计提 − 调减）检测
  • 加计抵减比例不在政策档位（5% / 10% / 15%）提示
  • 抵减前应纳税额为 0 或负数却仍有实际抵减提示

同名工具的完整档是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别就是上面这些，没有别的。

使用次数与完整档

本免费版每次运行结束后会向服务端做一次匿名次数统计：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），不发送你的材料、不写任何文件。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；

· 第 4 次起：服务端会返回一段完整档说明（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；

· 统计不可用（离线/超时/被拦截）时什么都不做，核对结果与退出码不受任何影响。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

边界（请务必知道）

  • 不做政策判断：你是否属于适用加计抵减的行业、适用 5% / 10% / 15% 哪一档、政策在某地某期是否仍有效

——这些请以主管税务机关口径为准，本工具只核你给的表内数字与勾稽关系；

  • 不代替增值税申报、不代填申报表，也不出具鉴证意见或税务意见；
  • 不核对进项发票真伪、勾选认证情况，也不比对开票系统与勾选平台的逐行明细；
  • 不读取电子税务局 / 开票系统的导出文件——需要你先导出成文本贴进来；
  • 材料不足（认不出表头、没有数据行、必需列缺失）时不给结论，只告诉你还缺什么。
