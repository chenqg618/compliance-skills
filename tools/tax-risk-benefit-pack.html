怎么用

node scripts/run.mjs --sample                 # 单客户样例（内置，5 项全跑）
node scripts/run.mjs --sample-batch           # 3 家客户的批量样例（干净 / 有硬伤 / 未交材料）
node scripts/run.mjs --input <客户目录>     # 批量：每个子目录 = 一家客户
node scripts/run.mjs --input <材料.json>        # 单客户：JSON 或纯文本

客户目录怎么放（每个子目录里放这家客户的一套材料，每项用 === 检查项 === 分段，Tab 分隔最稳）：

客户目录/
  豫州商贸有限公司（2026-02 申报后自查）/税费材料.txt
  中岳建材有限公司（2026-02 申报后自查）/税费材料.txt

结论怎么读

  • 每家客户一行：[结论] 客户名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行；
  • 有价值的是问题明细：每条都带 客户 + 检查项 + 来源文件:行号 + 类别 + 具体数字；
  • 「未执行」与「通过」是两件事：没交材料 / 材料认不出表 = 未执行，不是"没问题"。

常见错法

  • 把几家客户的材料放进同一个子目录：--input 指向的目录里，每个子目录 = 一家客户。混在一起时引擎只能按表头认出哪张表属于哪一项，认不出客户归属，结论就没有客户名。
  • 把 5 项的材料全塞进一个文件却不分段：引擎按 === 检查项 === 分段找每一项的表；不分段时除了第一项，其余四项都会落进「未执行」，看起来"没问题"其实是没核。
  • 以为「未执行」=「通过」：某个客户只交了 2 张表，那 2 项之外的是没有核，结论里会单列「未执行」，不要把它当成"这家没问题"。
  • 拿税负率预警阈值当结论：行业预警值只是提示比较，是不是异常要结合你的业务结构判断；本工具只保证"你填的数和算式对得上"，不给税务意见。
  • 拿 --sample 的输出当自己的结论：样例只是让你确认"跑得通、格式对"，里面的数字是虚构的，必须换成你自己的材料再跑。

使用次数与完整档

本免费版每次运行结束后会向服务端做一次匿名次数统计：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），不发送你的材料、不写任何文件。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；

· 第 4 次起：服务端会返回一段完整档说明（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；

· 统计不可用（离线/超时/被拦截）时什么都不做，核对结果与退出码不受任何影响。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

需要完整档时（可选）

本免费版是完整可用的核心产出，本版本不包含下面这些项：

  • 跨客户汇总台账（全部客户 × 全部 5 项自查合并成一张总表）

同名工具的完整档是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别就是上面这些，没有别的。

边界（请务必知道）

  • 不做：判断某项支出能不能抵扣、该适用哪档税率/征收率、优惠是否真的适用（属于税务判断，请咨询税务师或主管税务机关）；
