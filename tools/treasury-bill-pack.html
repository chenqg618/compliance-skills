资金与票据技能包（免费版）

完全本地运行：引擎已经打包在本技能里（scripts/engine/）。 核对过程不需要联网、不需要 API Key、没有调用次数上限、不写任何文件。

什么时候用

谁会在什么时候用：企业出纳、资金岗、总账会计与代账公司，在**月末结账、资金盘点、

票据到期前、与银行对账**这些固定节点上。

资金与票据底稿从来不是一张表：门店现金盘点差异、现金流预测与实际差异、银行流水对账（未达账项）、

银行承兑汇票台账与到期兑付、票据贴现利息、应付账款保理与贴现、逾期利息、银行贷款利息与还款计划、

备用金与报销核销、票据（发票）一致性、外币结算与汇兑损益、连锁门店调拨与库存、

仓库周转与呆滞库存、保函台账与到期失效 —— 每一张都有自己的勾稽关系，

逐张手核既慢又容易漏，而且月月都要重复一遍；

少记一笔未达账项、把贴现息算错、保函到期忘了注销，后果比多花半小时严重得多。

这个包做的事只有一件：--input <对象目录>（每个子目录 = 一个对象 / 一套材料），

一次跑完所有对象，每个对象一行结论。

这个免费版查什么

下面 14 项，每个对象都跑一遍（检查项名字与引擎 CHECKS_GIVEN 逐条一致）：

  1. 现金盘点差异核对
  2. 现金流预测与实际差异核对
  3. 银行流水对账核对
  4. 银行承兑汇票台账与到期兑付核对
  5. 票据贴现利息核对
  6. 应付账款保理与贴现核对
  7. 逾期利息核算核对
  8. 银行贷款利息与还款计划核对
  9. 备用金与报销核销核对
  10. 票据一致性核对
  11. 外币结算与汇兑损益核对
  12. 连锁门店调拨与库存核对
  13. 仓库周转与呆滞库存核对
  14. 保函台账与到期失效核对

引擎里的 CHECKS_WITHHELD（本免费版不执行的项）会逐条打印出来，例如

「跨对象汇总台账」「资金与票据风险排序清单」「跨对象共性问题归类」「资金票据台账导出」——

它们是"未执行的检查项"的说明文本，不是实现。

另外，每个成员检查包自己没做的子检查（SUB_CHECKS_WITHHELD，本包合计 75 项）也在结果里

scope.sub_checks_not_run 如实列出 —— 两个档位都没实现它们，不会因为「买了完整档」就让买家以为这些项被跑了。

怎么用

node scripts/run.mjs --sample                  # 单对象样例（内置）
node scripts/run.mjs --sample-batch            # 3 个对象的批量样例
node scripts/run.mjs --input 对象目录           # 批量：每个子目录 = 一个对象
node scripts/run.mjs --input 对象目录 --json    # 机器可读

对象目录怎么放（每个子目录里放该对象的一套资金与票据材料，每项用 === 检查项 === 分段，Tab 分隔最稳）：

对象目录/
  出纳组-2026-05/资金票据材料.txt
  门店A-2026-05/资金票据材料.txt

也可以把 14 张表拆成 14 个文件放进同一个子目录 —— 引擎会自己认表头找对应的那一项。

templates/sample.json 是引擎自己的样例，可以直接 --input 它先跑通一遍。

退出码：0 已执行检查 / 1 缺少入参 / 3 材料不足 / 4 入参读不到或无法解析 / 9 未预期错误。

材料不足（一个对象的材料都没有、材料为空或只有一两行、认不出任何一张表）时，

本工具不做任何认定、也不给任何结论，打印缺什么并以退出码 3 结束 —— 不会把"没查"说成"通过"。

结论怎么读

  • 每个对象一行：[结论] 对象名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行；
  • 有价值的是问题明细：每条都带 对象 + 检查项 + 来源文件:行号 + 类别 + 具体数字，

第三方可以拿同一份材料复算；

  • 行号一律以你的原文内容为准落位（成员引擎内部的行号口径不统一，本包只按"这一行在原文里真的存在"

来定位），所以拿行号回原文一定找得到那一行。

常见错法

  • 把 14 项的材料全塞进一个文件却不分段：引擎按 === 检查项 === 分段找每一项的表；

不分段时只有第一段能被认出，其余 13 项会如实标成「未执行」并报一条「材料只覆盖了一部分」，

不是"查过了没问题"。

  • 一个对象一个目录：--input 指向的目录里，每个子目录 = 一个对象。

把所有门店 / 所有期间的底稿放进同一个子目录，会被当成一个对象，跨对象的差异与汇总也就无从谈起。

  • 以为「未执行」=「通过」：某对象只交了 3 张表，那 3 项之外的 11 项是没有核，

结论里写的是「未执行」，并且会单独报一条覆盖缺口。

  • 把银行流水与银行对账单混着填：本包核的是"银行流水 ↔ 企业账面"两栏逐笔配对，

只贴一侧只会得到一堆"未达账项"，那不是错账，是少了一栏。

  • 拿 --sample 的输出当自己的结论：样例只是让你确认「跑得通、格式对」，

真正的结论必须来自你自己的材料。

使用次数与完整档

本免费版每次运行结束后会向服务端做一次匿名次数统计：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），不发送你的材料、不写任何文件。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；

· 第 4 次起：服务端会返回一段完整档说明（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；

· 统计不可用（离线/超时/被拦截）时什么都不做，核对结果与退出码不受任何影响。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

需要完整档时（可选）

本免费版是完整可用的核心产出，本版本不包含下面这些项：

  • 跨对象汇总台账（全部对象 × 全部 14 项检查合并成一张总表）
  • 资金与票据风险排序清单（按 P0/P1/P2 排序，带对象名与原文文件行号）
  • 跨对象共性问题归类（同一问题命中 2 个及以上对象时合并成一条共性项）
  • 资金票据台账导出（Markdown 与 CSV 文本，直接用于结账前复核说明与付款审批附件）

同名工具的完整档是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别就是上面这些，没有别的。

边界（请务必知道）

  • 不做某笔资金收付、贴现、保理、放款该不该做、金额该不该付的判断（属于业务与审批判断，

请按合同、授信与审批结论执行）；

  • 不核对银行回单 / 对账单 / 票据 / 发票 / 保函的真伪，也不查询供应商与客户的征信、失信名单；
  • 不代替审计，也不出具鉴证意见或审计意见；不判断利率、贴现率、汇率、保证金比例该取什么值；
  • 不读取网银 / ERP / 资金系统 / 票据系统的导出文件 —— 需要你先导出成文本，每个对象一个目录。
