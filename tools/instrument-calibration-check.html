计量器具检定校准到期核对（免费版）

完全本地运行：引擎已经打包在本技能里（engine/ 目录）。 核对过程不需要联网、不需要 API Key、没有调用次数上限。

什么时候用

谁会在什么时候用：计量管理员 / 质量部 / 实验室设备管理员，在每个月做计量核对（体系审核前的自查、内审前的准备、月度质量例会前）时用。

强制检定与校准的计量器具都有检定/校准周期：卡尺、千分尺、天平、压力表、温度计、电子秤、流量计、分光光度计、酸度计……

一旦到期未检定还在用，就是体系审核（ISO 9001 / ISO 17025 / GMP）与计量监管的直接不合格项，

而且这台器具量出来的数据都不再可信 —— 产品尺寸、配方称量、压力温度记录全都受影响。

每个月必须核对的动作：台账与检定证书是否齐、下次到期日是否还在覆盖期内、

停用/报废的器具是否还在现场用、校准结果是否满足最大允许误差。

这些动作手工做就是"拿两张表一行行对"，一台六七十台器具的台账要核半天，还容易漏。

这张表（材料）长什么样：一张含表头的计量器具台账，至少要有

器具编号 / 器具名称 / 型号规格 / 准确度等级 / 上次检定日期 / 校准周期(月) / 下次检定日期 / 证书编号 / 使用部门 / 状态；

台账后面可以再用 #证书明细# / #机构资质# / #使用记录# / #期间核查# 小标题附上对应的表。

这个免费版查什么（6 项）

  1. 到期覆盖核对：核对基准日 ≤ 下次检定日期；超期即报，给出超期天数与到期日原文。
  2. 台账与证书一致性：证书编号 / 检定日期 / 有效期在台账与证书两边对不上就报，并给出两处原文与行号。
  3. 校准周期勾稽：上次检定日期 + 校准周期(月) 是否等于下次检定日期（逐行复算，给出复算式）。
  4. 同一器具编号重复登记：同一器具编号在台账里出现两次以上（会让到期提醒漏、汇总台数翻倍）。
  5. 合计行/统计行逐列复核：合计行的数量类列必须等于明细行逐列累加。
  6. 空白/占位符/日期格式/状态值非法：日期必须是 2026-03-10 / 2026/03/10 / 2026年3月10日，状态必须收敛到 在用 / 停用 / 报废（可细分送检中、待检定）。

跑 node scripts/run.mjs --sample 会打印实际执行了哪些检查项，以及本版本不包含哪些。

怎么用

node scripts/run.mjs --sample                 # 先看样例

入参：{"text": "…"}，或直接把台账（含表头）从 Excel 复制成文本贴进去（Tab 分隔最稳）。

可选 {"text": "…", "asOf": "2026-06-30"} 指定核对基准日；不指定时用材料里最晚的使用/核查日期推算，

常见错法（计量管理里最容易出错的地方）

  1. 只登记「上次检定日期」，没有周期也没有下次到期日 —— 台账看着很齐，但下次什么时候送检完全靠人记，一忙就漏。到期提醒是算出来的，不是想起来的：上次检定日期 + 校准周期(月) 必须能推出下次到期日。
  2. 停用/报废器具留在台账里不改状态，人还在现场用 —— 台账写着"报废"、现场却贴着合格标签还在量，体系审核会直接开不合格项（现场撤出 + 停用标识 + 记录停止，三件事缺一不可）。
  3. 校准周期写成 12 个月，下次到期日却按"隔一年"随手填 —— 12 个月 ≠ 365 天：闰年、跨月、月末（1 月 31 日 + 1 个月 = 2 月 28 日）都会差一两天，手工填必然对不上。周期列与到期日列要能互相复算出来。
  4. 同一台器具换部门/换状态时新增一行，而不是改原来那条 —— 同一器具编号出现两次，到期提醒会漏掉其中一条、汇总台数还会翻倍（一台当成两台）。
  5. 证书编号只抄了后 6 位、有效期手抄错一位 —— 台账与证书对不上是最常见的"资料不符"；证书原件上的编号/检定日期/有效期必须与台账逐字一致（本工具会把两处原文都摆出来，改哪边由你定）。

需要完整档时（可选）

本免费版是完整可用的核心产出，本版本不包含下面这些项：

  • 最大允许误差（MPE）超差（实测误差绝对值 > 允许误差 ⇒ 报出超差量与超差倍数）
  • 停用/报废器具仍在使用记录里出现（跨表交叉核对）
  • 检定机构资质与证书有效期覆盖（机构授权有效期须晚于该器具的检定日期）
  • 期间核查/日常点检记录断档（按日期序列逐日比对，间隔超过核查周期即报）
  • 分部门×分器具类别的汇总清单（按超期天数排序，给出可整改动作）

同名工具的完整档是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别就是上面这些，没有别的。

使用次数与完整档

本免费版会在本包目录里记一个使用次数（scripts/.hint-count，一个整数，不含任何机器或用户信息）。

· 前 3 次：完全离线（不发生任何网络请求），输出与现在完全一样；

· 第 4 次起：服务端会返回一段完整档说明（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；

· 第 4 次起才会向服务端问一次（只发包标识与次数），拿回完整档说明；

· 请求不可用（离线/超时/被拦截）时什么都不做，核对结果与退出码不受任何影响；

· 不想要这次统计可以加 --no-stats（核对功能完全不受影响，只是拿不到完整档说明）。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

边界（请务必知道）

本工具不做引擎 CHECKS_OUT_OF_SCOPE 里列的那些判断：

不判定检定/校准结果本身是否合格、不判定器具是否属于强制检定目录、不读 .xlsx/.pdf 原件、核对过程不联网核验证书与机构资质真伪。

本版本只做上面这 6 项逐行算术与日期覆盖核对，不做最大允许误差超差、停用/报废器具跨表交叉核对、

检定机构资质覆盖、期间核查断档、分部门×分器具类别汇总清单 —— 那 5 项在完整版里，本包没有实现它们（CHECKS_WITHHELD 只是说明文本）。

材料不足时不给结论：会明确列出还缺什么，既不说"在有效期内"，也不说"已超期"，

更不会输出"未发现问题"。
