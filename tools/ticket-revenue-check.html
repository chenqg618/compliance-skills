票务收入与渠道结算核对（免费版）

完全本地运行：引擎已经打包在本技能里（scripts/engine/ 目录）。 核对过程不需要联网、不需要 API Key、没有调用次数上限。

本免费版只做票务金额与佣金的逐行复算与勾稽，不做票房真实性与税务核定。

它核的是你贴进来的这张表内部的算术与加总关系；票房是否真实、票款是否到账、

计税口径怎么定，都不在这个版本的能力范围内（详见下面的「不包含什么」与「边界」）。

什么时候用

谁会在什么时候用：演出 / 剧场 / 景区票务公司的财务、票务结算岗在

每月与各售票渠道（大麦、猫眼、官网、美团、抖音…）对账结算时，必须把这张

「票务收入与渠道结算明细表」核一遍才能确认收入、才能给渠道付款。

为什么每月都要核：渠道各给一张结算单，口径各不相同 —— 佣金率新旧混算、

退票只冲票面没冲佣金、赠票被算进票面、同一订单被两个渠道各结一次。

这几处每一处都能让一个月的收入差一截，而表里每一格都能被手算复现。

这张表会逐项核对什么：

· 票面收入 = 票数 × 票价

· 渠道佣金 = 票面收入 × 佣金率（佣金率按百分数填，8 表示 8%，填 8% 也认）

· 结算金额 = 票面收入 − 渠道佣金 − 退票金额

· 合计行各列 = 各明细行逐列相加（票数 / 票面收入 / 渠道佣金 / 退票金额 / 结算金额）

· 同一订单号重复结算、关键字段缺失与占位符、金额为负

每条结论都带原文行号与渠道 / 订单号，可被第三方用同一口径复算；

材料不足时不给结论，会明确列出还缺什么。

这个免费版查什么

  1. 票面收入勾稽（票数 × 票价 = 票面收入）
  2. 渠道佣金复算（票面收入 × 佣金率 = 渠道佣金，佣金率按百分数填）
  3. 结算金额逐行复算（票面收入 − 渠道佣金 − 退票金额 = 结算金额）
  4. 合计行与明细勾稽（合计行各列 = 各明细行逐列相加）
  5. 同一订单号重复结算检测
  6. 关键字段缺失、占位符与负数检测

（检查项由引擎的 CHECKS_GIVEN 导出，跑 --sample 会打印实际执行了哪些。

本版本不包含的检查项列在 CHECKS_WITHHELD 里 —— 不做也不假装做，而且不会用默认值编造结论。）

怎么用

node scripts/run.mjs --sample                     # 先看样例（样例本身就是一张干净的明细表）
node scripts/run.mjs --input 你的材料.json         # 跑自己的材料
node scripts/run.mjs --input 你的材料.json --json  # 机器可读输出

入参就是含表头的一张表（{"text": "结算期间\t场次\t渠道\t票档\t订单号\t票数\t票价\t票面收入\t佣金率\t渠道佣金\t退票金额\t结算金额\t备注"}）：

从 Excel 或票务系统 / 渠道对账单导出里直接复制成文本（Tab 分隔最稳）贴进去即可。

表头缺列会明确告诉你缺哪列 —— 缺一列就报缺列，不会按 0 替你假设"这个渠道没有退票、没有佣金"。

出参

--json 输出 { ok, tier, capability, checks_given, checks_withheld, result }，其中 result 里有：

· scope：本次执行了哪些检查（checks）、没执行哪些（checks_not_run）、

行数、期间数、渠道数、场次数、票数 / 票面收入 / 佣金 / 退票 / 结算的合计，以及 totals_row / totals_rows；

· findings：每条带 level（P0 / P1）、category、line（原文行号）、message（含渠道与订单号）、advice；

· summary：条数与 verdict（ERROR_FOUND / NEEDS_REVIEW / NO_ISSUE_FOUND）；

· checks_out_of_scope：本工具的边界。

退出码：0 已执行检查 / 1 没给入参 / 3 材料不足（不给结论） / 4 入参读不到或无法解析 / 9 未预期错误。

常见错法（本产品专属）

  1. 佣金率按错档 / 把百分数当小数：同一渠道同一票档在同一结算期通常只应有一个佣金率。

把 8% 填成 0.08（本工具按百分数解析，会算出 0.08% 的佣金）、

或续约后新旧费率混着算，一整列佣金会差几十倍；这条错还会顺着算式把结算金额一起带错。

  1. 退票只冲了票面、没冲佣金：退票要同时冲回票面收入所对应的渠道佣金。

只减票面不减佣金，结算金额就比渠道对账单多出「退票金额 × 佣金率」这一块；

把上期的退票挂到本期，则两个月都对不上。

  1. 退票归属记错行 / 记错渠道：退票必须退回原售票渠道原票档的行上。

把整场的退票都压在一个渠道上，那个渠道的退票额会超过它自己的票面收入；备注栏留空则说不清归属。

  1. 赠票 / 工作票 / 内部票混进票面：票面收入这一列应当是实际售票的金额。

把赠票算进去，票面收入就与「票数 × 票价」对不上（或者票数被改大）；

这种表内部还自洽（佣金按错的票面重算过），只看算术看不出来，必须拿售票系统原始流水核。

  1. 同一订单被两个渠道各结一次：渠道串单（两个渠道的对账单里都含这张订单）

或本期把上期已结的订单又抄了一遍，就是重复确认收入 —— 这是本工具一定会拦下来的一条。

  1. 留空与填 0 混用：退票金额填 0.00 表示"本期确实没有退票"，留空表示"不知道"。

留空时本工具不会替你按 0 算，会直接报这一格缺失；同理，负数（如退票填 -500）也会单独报出来。

这个免费版不包含什么

本版本不执行下面这些检查（它们是完整档才做的，CHECKS_WITHHELD 里逐条列出）：

  • 退票归属判定（退票金额超过本行票面收入，或退了票而备注里没有说明退票归属）
  • 跨期结算判定（场次日期所在月份与该行结算期间不一致）
  • 佣金率不一致判定（同一渠道同一票档在同一结算期里出现多个佣金率）
  • 票面口径不一致判定（同一渠道同一票档出现多个票价）
  • 跨渠道 / 跨场次汇总台账（按渠道、按场次分别汇总票数、票面收入、佣金、退票与结算金额）
  • 按差异金额排序的处理清单（逐条带原文行号与订单号，标出差异金额与差异原因）

同名工具的完整档是另一个独立商品（条款与条件以它自己的商品页为准）；

两档的差别就是上面这些，没有别的。本免费版是完整可用的核心产出，上面这些不做也不假装做。

使用次数与完整档

本免费版会在本包目录里记一个使用次数（scripts/.hint-count，一个整数，不含任何机器或用户信息）。

· 前 3 次：完全离线（不发生任何网络请求），输出与现在完全一样；

· 第 4 次起：服务端会返回一段完整档说明（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；

· 第 4 次起才会向服务端问一次（只发包标识与次数），拿回完整档说明；

· 请求不可用（离线/超时/被拦截）时什么都不做，核对结果与退出码不受任何影响；

· 不想要这次统计可以加 --no-stats（核对功能完全不受影响，只是拿不到完整档说明）。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

边界（请务必知道）

本工具不做引擎 CHECKS_OUT_OF_SCOPE 里列的那些判断：

· 不判断票房是否真实（有没有锁场、包场、刷单、赠票混入票面），也不核上座率；

· 不判断票款是否真实到账、渠道回款与银行流水是否一致；

· 不做任何税务申报核定（计税收入口径、发票税额、税会差异、文化事业建设费一律不管）；

· 不判断佣金率该按哪一版渠道合同、佣金是否含税、渠道服务费该不该另计；

· 不读 Excel / 票务系统 / 渠道对账单导出文件（需要你先导出成文本贴进来）。

材料不足时不给结论，也不会输出「未发现问题」；

表里的票数、票价、佣金率、退票金额一律以你填的为准。

本免费版每次运行结束后会向服务端做一次匿名次数统计：只发送本包标识与一个不含材料的匿名安装标识，
