审计调整分录核对（免费版）

完全本地运行：引擎已经打包在本技能里（engine/ 目录）。 不联网、不需要 API Key、没有调用次数上限。

什么时候用

谁会在什么时候用：年审期间，审计师把调整分录建议（审计调整）交过来，

财务要在这张审计调整分录核对表上逐条落实、并与审计师来回核对清楚 —— 调错一行，报表就是错的。

这张表会逐项核对什么：一张表里每一行 = 一条调整分录的一个科目（借方或贷方一侧）。

本工具把表里能算出来的东西全部复算一遍：

  1. 借贷差额复算（借贷差额 = 借方合计 − 贷方合计，必须为 0）
  2. 科目净影响复算（借方金额 − 贷方金额 = 科目净影响）
  3. 合计行逐列复核（合计行 = 各明细行逐列相加）
  4. 同一调整事项重复行检测（整行重复粘贴 = 调整被算两次）
  5. 空白与占位符检测（编号/科目名称空着、借贷两列都没填、金额列写着"待填"）
  6. 金额为负检测（红字冲销请单独列示，别与正常分录混在一起）

（检查项的权威清单在引擎的 CHECKS_GIVEN / CHECKS_WITHHELD 里，跑 --sample 会打印实际执行了哪些。）

每条结论都带原文行号与出处（line 就是表里的第几行），可被第三方用同一口径复算；

材料不足时不给结论，会明确列出还缺什么（例如缺「借方金额」这一列）。

怎么用

node scripts/run.mjs --sample                 # 先看样例
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料

入参写法：{"text": "（把你那张表的表头和若干行一起复制进来，Tab 分隔最稳）"}；

也可以直接把核对表从 Excel 复制成文本存成文件传给 --input。

常见错法（这张表里真的会有人这么填）

  1. 借贷两边抄得不平：调整分录的借贷必须相等。少抄一行、方向写反、小数位看错，都靠"借方合计 − 贷方合计"当场暴露；同一笔调整的这两边必须写同一个调整事项编号，否则连"是不是同一笔"都判不出来。
  2. 「科目净影响」按余额方向填反：净影响 = 借方 − 贷方（贷方一侧是负数），不是"增加为正"。这是报表科目串位最常见的来源。
  3. 同一笔调整拆成多行却不写编号 / 不写说明：编号是把它与审计师的调整建议、底稿对上的钥匙；说明是判断"影响科目与金额是否与调整事项一致"的唯一依据。
  4. 整行复制粘贴导致重复调整：一行重复 = 调整被算两次。本工具按"事项 + 科目 + 借贷金额 + 净影响 + 说明"整行比对。
  5. 合计行手改：手改过的合计行与明细对不上；本工具会逐列复算合计行（借贷金额、科目净影响）。

边界（请务必知道）

本工具不做引擎 CHECKS_OUT_OF_SCOPE 里列的那些判断 —— 例如"这笔调整的会计处理对不对""科目用得对不对""要不要调、要不要披露"，

材料不足时不给结论，也不会输出「未发现问题」。
