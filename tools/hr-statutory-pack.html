人力法定费用技能包（免费版）

完全本地运行：引擎已经打包在本技能里（scripts/engine/）。 核对过程不需要联网、不需要 API Key、没有调用次数上限、不写任何文件，材料不出本机。

什么时候用

集团/多主体的 HR 与财务共享中心，在每年残保金申报、每月工会经费计提、年度汇算福利费限额之前。

典型场景：月度/季度复核前，把一类检查一次跑完所有公司

这个免费版查什么

一次跑完所有公司，每家公司一行结论（免费版的核心产出，完整可用）：

  1. 残疾人就业保障金核对 —— 复用 parts/disability-fund-check/（逐字节来自免费包 disability-fund-check-free）
  2. 工会经费计提与上缴核对 —— 复用 parts/union-reserve-check/（逐字节来自免费包 union-reserve-check-free）
  3. 职工福利费与教育经费限额核对 —— 复用 parts/welfare-limit-check/（逐字节来自免费包 welfare-limit-check-free）
每一项的实际规则在 scripts/engine/parts/<检查项>/ 里（逐字节复用仓库里已有的免费引擎， 一行规则都没有改）。本包只做"目录 → 公司 → 逐项派发"的编排。

怎么用

node scripts/run.mjs --sample                 # 单公司样例（内置，3 项全跑）
node scripts/run.mjs --sample-batch           # 3 家公司的批量样例（干净 / 有硬伤 / 未交材料）
node scripts/run.mjs --input <公司目录>     # 批量：每个子目录 = 一家公司
node scripts/run.mjs --input <材料.json>        # 单公司：JSON 或纯文本

公司目录怎么放（每个子目录里放这家公司的一套材料，每项用 === 检查项 === 分段，Tab 分隔最稳）：

公司目录/
  豫州制造主体（2026 年度人力费用）/人力费用材料.txt
  中岳商贸主体（2026 年度人力费用）/人力费用材料.txt

结论怎么读

  • 每家公司一行：[结论] 公司名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行；
  • 有价值的是问题明细：每条都带 公司 + 检查项 + 来源文件:行号 + 类别 + 具体数字；
  • 「未执行」与「通过」是两件事：没交材料 / 材料认不出表 = 未执行，不是"没问题"。

常见错法

  • 把几家主体的材料放进同一个子目录：--input 指向的目录里，每个子目录 = 一家主体。混在一起时结论里就没有主体名，跨主体台账也分不出是谁。
  • 在职职工人数用了期末数：残保金按上年在职职工人数的口径算，用期末人数或当月人数会让保障金算错，而且和申报表对不上。
  • 安排残疾人比例按"人数/人数"直接除：比例要用安排残疾人就业人数 ÷ 在职职工人数，并注意重度残疾人按 2 人计的口径；除错了整张表都偏。
  • 工会经费只记计提不记上缴：计提数与实际上缴数、返还数要能对上；只填一个数时该项会落进「未执行」，不是"通过"。
  • 拿 --sample 的输出当自己的结论：样例数字是虚构的，必须换成你自己的材料再跑。

使用次数与完整档

本免费版每次运行结束后会向服务端做一次匿名次数统计：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），不发送你的材料、不写任何文件。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；

· 第 4 次起：服务端会返回一段完整档说明（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；

· 统计不可用（离线/超时/被拦截）时什么都不做，核对结果与退出码不受任何影响。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。
