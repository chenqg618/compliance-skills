加盟保证金与费项结算核对（免费版）

完全本地运行：引擎已经打包在本技能里（engine/ 目录）。 核对过程不需要联网、不需要 API Key、没有调用次数上限。

本免费版只做金额逐行复算与勾稽，不做合同条款与合规性判定。

什么时候用

谁会在什么时候用：连锁加盟总部（或区域代理）的财务 / 结算岗，

在每月与加盟商对账、出结算单、或者加盟商拿着结算单来说"对不上"的时候，

必须把这张加盟商保证金与费项结算明细表核一遍才能收款 / 划款 / 退保证金。

每月都要吵的就是这几处：保证金余额与「期初 + 收取 − 退还 − 扣罚」对不上、

加盟费 / 管理费金额与「计费基数 × 费率」对不上、同一笔费项计了两遍、

扣罚扣得比可扣的保证金还多、关键格留空或写成「待填」。

这张表会逐项核对什么（每一步都能被第三方用同一份输入手算复现）：

  • 保证金余额 = 保证金期初 + 保证金收取 − 保证金退还 − 保证金扣罚
  • 费项金额 = 计费基数 × 费率
  • 合计行各列 = 各明细行逐列相加（合计行没填的列不核）
  • 同一加盟商同一结算期间同一费项、且金额相同的重复计费
  • 扣罚超过可扣保证金（余额会变负）/ 扣罚超过「合同扣罚上限」列
  • 关键字段缺失或为占位符、金额列为负数

每条结论都带原文行号与加盟商 / 费项，可被第三方用同一口径复算；

材料不齐时不给结论，会明确列出还缺什么。

这个免费版查什么

  1. 保证金余额复算（保证金余额 = 保证金期初 + 保证金收取 − 保证金退还 − 保证金扣罚）
  2. 费项金额复算（费项金额 = 计费基数 × 费率）
  3. 合计行与明细勾稽（逐列：合计行 = 各明细行逐列相加；合计行没填的列不核）
  4. 同一加盟商同一期间同一费项、且费项金额相同的重复计费检测
  5. 扣罚超过可扣保证金（余额为负）/ 超过合同扣罚上限检测
  6. 关键字段缺失或为占位符、金额列为负数检测

（检查项由引擎的 CHECKS_GIVEN 导出，跑 --sample 会打印实际执行了哪些；

本版本不包含的 5 项列在 CHECKS_WITHHELD 里，不做也不假装做。）

数字会做归一化：120,000.00、千分位、带货币符号的写法、(1200)（会计负数）都被认成同一个口径；

费率写 3、3% 或 0.03 都按 3% 理解（写 1 表示 100%，本工具不会替你猜你的意思）。

表头里的空格与括号会被忽略，所以「保证金余额(元)」和「保证金余额」都认。

余额口径：保证金期初 / 收取 / 退还 / 扣罚四列都按"截至本期"填写，余额应当能被这四列复算出来；

跨期的正确填法是上期期末余额 = 本期期初。

常见错法（本产品专属）

  1. 保证金余额没把某一笔发生额算进去：最常见的是上期期末没结转成本期期初、

退还款没从余额里减、或者扣罚只在备注里写了却没落进金额列。

余额一错，后面所有"这一户该收多少 / 该退多少"的结论都跟着错，所以这一条永远排在最前面。

  1. 费率用了合同里另一档：同一加盟商同一期间同一费项，合同里可能按门店数 / 营收规模分档。

费率列写 3、3%、0.03 都按 3% 理解；写成 1 意思是 100%，费项金额当场变成"整笔基数"，

差出好几个数量级。本工具不会替你猜你的意思。

  1. 明细改对了、合计行忘了重算：合计行是对外金额（据此向加盟商收款 / 划款），

明细单改过之后合计没跟着刷新，或者明细里漏了整整一行 —— 逐单都对而合计对不上时，

差异就出在合计行自身。

  1. 同一笔费项计了两遍：重复导单 / 复制黏贴时，同一加盟商同一期间同一费项会出现两行、

连金额都一模一样。本工具只把「金额也相同」的判为重复计费，

按不同费率档位正当拆行的两行不会被误报。

  1. 扣罚扣超了：扣罚只能扣到保证金余额为 0 为止；扣超的部分要么另行追缴、要么按合同由其他款项抵。

另外「合同扣罚上限」这一列只是你自己填的上限，本工具只做算术比较，

不判断上限填得对不对、也不判断这笔扣罚是否合规。

  1. 该填 0 的格子留空：确实没有发生的收退 / 扣罚留空，会让这一行整行复算不出来。

留空就是"不知道"，本工具宁可报缺格，也不用 0 替你假设。

不包含什么

以下检查项不在本版本范围内，调用时也不会执行（列在引擎的 CHECKS_WITHHELD 里）：

  • 跨加盟商 × 跨期间汇总台账（按加盟商与按结算期间归集费项金额、保证金收发扣与争议金额，

并逐户做「期初 + 收取 − 退还 − 扣罚 = 期末」的余额勾稽）

  • 按差异金额排序的处理清单（带原文行号、加盟商、结算期间、费项与建议动作）
  • 差异归因：费率档位不一致（同一加盟商同一期间同一费项出现多个费率 ⇒ 按其中最低费率折算多计金额）
  • 差异归因：基数口径不一致（同一加盟商同一期间同一费项出现多个计费基数 ⇒ 按其中最低基数折算多计金额）
  • 差异归因：扣罚缺少依据说明，以及跨期归属错位（保证金期初 ≠ 上期期末余额 / 一次性费项出现在多个结算期间）

本免费版只做金额逐行复算与勾稽，不做合同条款与合规性判定：

费率该用哪一档、基数该取什么口径、扣罚是否合规、合同条款是否合法有效，都不在本版本的判断范围内。

同名工具的完整档是另一个独立商品（条款与条件以它自己的商品页为准）；

两档的差别就是上面这些，没有别的。

本免费版每次运行结束后会向服务端做一次匿名次数统计：只发送本包标识和一个不含任何材料的匿名安装标识，

  • 第 4 次起：服务端会返回一段完整档说明（完整档是另一个独立商品，条款与条件以它自己的商品页为准），届时才会打印这一行；
  • 统计不可用（离线 / 超时 / 被拦截）时什么都不做，核对结果与退出码不受任何影响；
  • 不想要这次统计可以加 --no-stats（核对功能完全不受影响，只是拿不到完整档说明）。

核对本身全部在本机用 Node 标准库完成，不调用任何模型、不连接加盟商结算系统或银行。
