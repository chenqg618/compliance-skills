猎头服务费与保证期退款核对（免费版）

完全本地运行：引擎已经打包在本技能里（engine/ 目录）。 核对过程不需要联网、不需要 API Key、没有调用次数上限。

什么时候用

谁会在什么时候用：HR / 财务在收到猎头服务费账单、准备请款或月末对账时，

必须把这张表核一遍才能往下走。

具体场景：猎头供应商发来一张账单（一行一个候选人），合同里写着「候选人年薪 × 服务费率」，

以及「候选人在保证期（常见 90 天）内离职，按未满天数比例退还服务费」。

付款之前你要确认：账单里的服务费是不是按约定费率算的、该退的退款有没有退、合计行与明细对不对得上。

这张表会逐项核对什么：猎头服务费账单与保证期明细表的逐行算术、保证期退款口径、合计勾稽、重复与空缺。

这个免费版查什么

  1. 服务费复算：候选人年薪 × 服务费率 = 服务费，逐行复算（年薪与服务费率一律以你填的为准，不套默认值）。
  2. 保证期退款复算：保证期内离职 ⇒ 应退比例 = (保证期天数 − 已服务天数) ÷ 保证期天数、应退金额 = 服务费 × 应退比例；非保证期内离职 ⇒ 应退比例与应退金额都应为 0。
  3. 账单合计勾稽：合计行的服务费 / 应退金额 / 实退金额 = 各明细行逐列相加（公差 1 分）。
  4. 同一候选人重复计费检测：同一供应商 + 同一候选人 + 同一月份出现多行。
  5. 服务费率超合同上限检测：服务费率 > 合同费率上限。
  6. 关键字段缺失 / 占位符 / 负数检测：空白、「待填」这类占位符、负金额。

每条结论都带原文行号与候选人，可由第三方用同一份输入复算；

材料不足时不给结论，会明确列出还缺什么（缺列、只有表头、空正文都会如实说明）。

服务费 / 合同费率上限 / 保证期天数 / 保证期内离职 / 已服务天数 / 应退比例 / 应退金额 / 实退金额。

出参

  • status：success 表示真的执行了检查；insufficient_input 表示材料不足 —— 此时不给结论，也不会输出「未发现问题」。
  • result.findings[]：每条含 line（原文行号）、level（P0 必须改 / P1 需确认 / P2 提示）、category、message、who（月份 + 供应商 + 候选人）。
  • result.scope：本次执行的检查项、明细行数、月份数与供应商数、服务费 / 应退 / 实退合计、withheld（本版本未执行的检查项）、totals_row（是否认出了合计行）。
  • result.summary.verdict：ERROR_FOUND（有 P0）/ NEEDS_REVIEW（只有提示）/ NO_ISSUE_FOUND。

常见错法（本产品专属）

  1. 服务费不是按「年薪 × 服务费率」算的 —— 拿月薪直接乘费率，或者用年度总包（含奖金、股权）当分母

却仍按基础年薪谈定的费率。服务费率一律按百分数填：20% 与 20 都表示 20%，写成 0.2 会被当成 0.2%。

  1. 保证期内离职退错比例 —— 拿 365 天当分母（按年度口径折），或者按整月数硬砍（入职 45 天离职按 2 个月算）。

约定口径是保证期天数做分母的自然日折算，不是 365 天、也不是整月。

  1. 已服务天数填成「在职月数」或从入职到本月的天数 —— 保证期退款的分子分母都用自然日；

填成整月会让退款比例整列偏掉，而且不会报错，只会算少。

  1. 同一候选人同一月份被建了两行 —— 一个岗位先按预估年薪开一次账单、offer 定稿后又按实际年薪补一行，

两行都在就等于重复计了一遍费。本工具按「供应商 + 候选人 + 月份」判重，不靠名字写法是否一致。

  1. 合计行是手打或从上一版复制的 —— 明细改过合计没改；或者合计行只填了服务费，

应退 / 实退两列留空，等于这两列根本没参与对账。合计是请款与对账的取数口径，对不上就是三方都对不上。

使用次数与完整档

本免费版每次运行结束后会向服务端做一次匿名次数统计：只发送本包标识和一个不含任何材料的

匿名安装标识，不发送你的材料、不写任何业务文件。

  • 前 3 次：服务端不返回任何内容，输出与现在完全一样；
  • 第 4 次起：服务端会返回一段完整档说明（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
  • 统计不可用（离线 / 超时 / 被拦截）时什么都不做，核对结果与退出码不受任何影响。

本版本不包含的检查项见上一节。
