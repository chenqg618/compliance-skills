销售返利与渠道返点核对（免费版）

完全本地运行：引擎已经打包在本技能里（engine/ 目录）。 核对过程不需要联网、不需要 API Key、没有调用次数上限。

什么时候用

谁会在什么时候用：快消/建材/家电等有渠道返利的销售财务与商务，在月度计提返利、季度/年度兑付之前：

  • 应计返利 = 计算基数 × 返利比例；
  • 期末已计提未兑付 = 期初已计提 + 本期计提 − 本期实际兑付；
  • 本期实际兑付不得超过（期初 + 本期计提），否则就是超兑。
与已有产品的关系：purchase-rebate-check（采购返点）核的是应向供应商收取的返利；本产品核的是 应付给客户/渠道的返利负债（先计提、后兑付）——两侧口径与勾稽关系不同。

这个免费版查什么

  1. 合计行逐列复核（计算基数/应计返利/期初已计提/本期计提/本期实际兑付/期末已计提未兑付）；
  2. 应计返利 = 计算基数 × 返利比例（容差 0.02，P0）；
  3. 期末未兑付 = 期初已计提 + 本期计提 − 本期实际兑付（P0）；
  4. 本期实际兑付为负（P0）；
  5. 应计返利为负（P1）；
  6. 客户/渠道+返利政策重复行检测；
  7. 空白与占位符检测（含必需列缺失，仍照常给结论）。

常见错法（这些表里真的会有人这么填）

  1. 比例填 3 而不是 3%：本工具两种写法都认（3 按 3 个百分点、0.03 按 3%），但别把 0.03 当成 0.03 个百分点——比例口径要在全表统一。
  2. 基数用含税销售额：返利基数通常按不含税销售额或政策约定的口径，用含税会让应计返利整体偏高。
  3. 先兑付后计提：本期兑付超过"期初 + 本期计提"就是超兑，会被完整档直接点出来——兑付前要先确认计提依据。
  4. 渠道层级重复计算：同一笔销售既给经销商返利又给门店返点（重复计入同一基数）会报重复行或比例失真。
  5. 兑付方式留空：兑付方式（银行转账/抵扣货款/平台账单抵扣）影响后续核销，留空无法复核。

使用次数与完整档

本免费版每次运行结束后会向服务端做一次匿名次数统计：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），不发送你的材料、不写任何文件。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；

· 第 4 次起：服务端会返回一段完整档说明（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；

· 统计不可用（离线/超时/被拦截）时什么都不做，核对结果与退出码不受任何影响。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

需要完整档时（可选）

本免费版是完整可用的核心产出，本版本不包含下面这些项：

  • 本期实际兑付超过 期初已计提 + 本期计提（超兑）检测
  • 返利比例不在常见档位（0~20%）提示
  • 期末已计提未兑付为负检测
  • 返利比例为 0 但应计返利 > 0（口径矛盾）检测
  • 兑付方式空白或「待定」提示

同名工具的完整档是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别就是上面这些，没有别的。

边界（请务必知道）

  • 不做会计判断：返利该冲减收入还是计入销售费用、何时确认，请按准则与公司政策判断；
  • 不代替审计程序或出具鉴证意见，也不判断返利政策是否构成价格折让；
  • 不核对返利协议、结算单、银行回单的真伪，也不与渠道系统逐行比对；
  • 不读取 CRM / 渠道系统 / 财务系统的导出文件——需要你先导出成文本贴进来；
  • 不判断返利的发票与税前扣除口径（属于税务判断）。
