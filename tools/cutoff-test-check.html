什么时候用

谁会在什么时候用：审计与月结/年结的财务，在期末结账与出报表之前。

截止性（cutoff）是审计第一个抽的样本：期末前后几天的发货、开票、入库、退货必须记在正确的期间；

记错期间会同时虚增/虚减两个期间的收入或成本：

  • 记账期间 = 业务日期所属期间（跨期即截止性错误）；
  • 业务日期不得晚于记账期间末日（先记账后发生）；
  • 期后事项金额 ≤ 原单据金额；期末最后 3 天的样本要写明处理说明。

这个免费版查什么

  1. 合计行逐列复核（单据金额 / 期后事项金额）；
  2. 记账期间 = 业务日期所属期间（跨期即截止性错误，P0）；
  3. 业务日期不得晚于记账期间末日（先记账后发生）；
  4. 单据金额为零检测；
  5. 单据类型口径提示（发货单 / 销售发票 / 入库单 / 出库单 / 退货单）；
  6. 同一单据号重复行检测；
  7. 空白与占位符检测（含必需列缺失）。

常见错法（这些底稿里真的会有人这么填）

  1. 业务日期填成"记账日期"：两列填成同一天，跨期永远查不出来；业务日期必须是最初发生的那一天。
  2. 记账期间只写"2026-01"但业务日期写"1月31日"（缺年份）：日期解析会跳过，该报的跨期不报；两列都要写全年份。
  3. 期后事项金额留空：留空等于没有期后事项，月末退货就会被漏掉；没有就填 0.00。
  4. 同一张发货单在两个月各贴一行（月结重贴）：会报重复行；跨期调整请用红冲单号单独列示。
  5. 期末最后 3 天的样本不写处理说明：完整档会点出来——审计要看的正是这几天的"依据"。

需要完整档时（可选）

本免费版是完整可用的核心产出，本版本不包含下面这些项：

  • 跨期超过 30 天（跨两个及以上期间）检测
  • 期后事项金额超过原单据金额检测
  • 期末最后 3 天的单据未填写处理说明提示（截止性重点样本）
  • 期后事项金额为负（应作为红冲处理）提示
  • 跨期单据数量占比超过 20% 提示（整体期间归属可信度下降）

使用次数与完整档

本免费版每次运行结束后会向服务端做一次匿名次数统计：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），不发送你的材料、不写任何文件。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；

· 第 4 次起：服务端会返回一段完整档说明（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；

· 统计不可用（离线/超时/被拦截）时什么都不做，核对结果与退出码不受任何影响。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

边界（请务必知道）

  • 不做会计判断：某笔交易实质上属于哪一期（是否满足收入确认条件、控制权是否转移）需按准则判断；
  • 不代替审计抽凭程序，也不出具审计或鉴证意见；
  • 不核对发票、发货单、入库单的真伪，也不与业务系统的逐行明细比对；
  • 不读取 ERP / 开票系统 / 仓储系统的导出文件——需要你先导出成文本贴进来；
  • 不判断跨期事项对所得税的影响（属于税务判断）；
  • 材料不足（认不出表头、没有数据行、必需列缺失）时不给结论，只告诉你还缺什么。
