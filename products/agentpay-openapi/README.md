# 机械核对型能力 API —— OpenAPI 3.0 规格

`openapi.json` 是我们按次计费能力的**标准 OpenAPI 3.0.3 规格**。
Coze 的 API 插件、以及多数智能体平台导入的都是这个格式 —— 有了它，"把能力变成插件"就是**一次导入**，
而不是照着文档手填。

## 覆盖什么

| 路径 | 用途 |
|---|---|
| `GET /api/v1/capabilities` | 能力目录（含免费端点、档位、输入说明） |
| `POST /api/v1/try` | **免费核对**（粘贴正文即可）；带 `X-API-Token` 时按已购额度跑完整版 |
| `POST /api/v1/<能力 id>` | 该能力的完整版（按次 ¥0.30 / ¥0.99 / ¥4.99 / ¥9.99；**14 个能力全覆盖**） |

## 一个重要事实：**每个能力端点都接受纯文本 `text`**

这对插件平台很关键 —— 文本进、文本出，不需要拼结构化 JSON。

```json
POST /api/v1/three-way-match
{ "text": "采购订单\n采购订单号: PO-1\n…\n\n入库单\n…\n\n发票\n…" }
```

多份材料用**单独一行的分节标题**或空行分隔；银行对账用「银行」「账面」两节。
（这一点是**实测过的**：14 个端点逐个用官方示例调用，全部通过预检到达计费关口。）

## 计费与凭证

- 不带凭证 → **HTTP 402** + `Payment-Needed` 响应头（内含账单）；
- 带 `X-API-Token: sk_…`（已购额度）→ 直接返回结果并核销一次；
- **失败不扣**：入参不合法或材料不足都会在计费前被拦下，且明确说明"没有向你收费"。

## 重新生成

规格是**从 `server.js` 的 CAPABILITIES 生成的**，不要手改：

```bash
python3 tools/build_openapi.py          # 重建
python3 tools/build_openapi.py --check  # 校验是否最新（已接入 npm run verify）
```

生成器里带**自检**：CAPABILITIES 块里出现几个 `id`，就必须产出几条 ——
数量对不上会直接失败（第 158 轮就是因为一条注释夹在 `id` 与 `tier` 之间，静默漏掉了一个能力）。
