# 三单匹配怎么做：付款前那一步的完整口径

> "三单匹配"是应付账款的标准动作：**采购订单（PO）、入库单（GRN）、发票（Invoice）**三张单据核对一致后才付款。
> 漏掉这一步的常见后果是**多付、错付、重复付款** —— 都是直接的钱。

## 一、为什么要三张，不是两张

- 只有订单 + 发票 → 可能**货没收到就付了钱**；
- 只有入库单 + 发票 → 可能**买了没订的东西**（无授权采购）；
- 只有订单 + 入库单 → 还没到付款环节。

三张凑齐，才能同时证明"**订了、收了、该付**"。

## 二、要核对什么（按重要性排序）

### 1. 关键字段跨单据一致（最先看）

| 字段 | 为什么 |
|---|---|
| 采购订单号 | 对不上说明配错了单 —— 这是最严重的一类 |
| 供应商名称 | 差一个字都可能是两个主体（"有限公司" vs "有限责任公司"） |
| 物料/品名 | 型号写错就是买错东西 |
| 数量、单价、金额 | 直接是钱 |

**注意**：只出现在一张单据上的字段**不要报** —— 无从比对的事情只能靠猜，猜就是错。

### 2. 行内算术（最容易被忽略）

- 数量 × 单价 = 金额
- 不含税金额 + 税额 = 价税合计

这两条是**纯算术**，算得出来就一定能判对错。供应商报价单里的算术错误相当常见，
而它们会一路带进付款金额。

### 3. 容差核对（三组）

| 比什么 | 常见容差 |
|---|---|
| 发票数量 vs 入库数量 | 0 或者很小的比例（短装/溢装要事先约定） |
| 发票金额 vs 订单金额 | 通常允许很小比例，超出要有人批 |
| 订单数量 vs 入库数量 | 分批到货时按累计比 |

容差**必须显式给**。不给容差、用默认值"必须完全一致"，会报出一堆正常的分批到货差异，
人看烦了就不再信任报告 —— 这比漏报更糟。

### 4. 重复发票号（重复付款线索）

同一张发票号在一批单据里出现两次，是重复付款最直接的信号。
**注意区分**：同一张发票分两次入账（预付+尾款）是正常的，所以要给出来让人判断，而不是直接判定。

### 5. 日期逻辑

订单日期 ≤ 入库日期 ≤ 发票日期。反过来通常意味着录错了。

## 三、做的时候最容易犯的三个错

1. **拿金额相近的两笔当同一笔对上** —— 金额必须**完全相等**才算配上，相近只能作为"可疑"另行提示；
2. **一个字段只在一张单据上出现就报不一致** —— 那是没法比，不是不一致；
3. **把"没查出问题"当成"没问题"** —— 没查出问题只说明**在你设定的检查范围内**没问题，
   不等于这笔付款就该发生。审批流、供应商资质、发票真伪，都不在AI核对的范围里。
