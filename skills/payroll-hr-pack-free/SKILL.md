# 薪酬社保与人力技能包（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`scripts/engine/`）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**、**不写任何文件**。

## 什么时候用

**谁会在什么时候用**：企业薪酬岗、人事、代账公司的工资社保岗，在**每月发薪与社保申报之前**。
薪酬底稿从来不是一张表：工资表发放前核对、应付职工薪酬勾稽、工资代发与银行回单核对、
代扣个税社保与申报核对、个税累计预扣核对、社保缴纳明细核对、社保缴费基数核对、
住房公积金缴存核对、加班费核对、计件工资核对、年终奖（奖金池）核对、提成与底薪核对、
销售阶梯提成核对、农民工工资专户核对 —— 每一张都有自己的勾稽关系，逐张手核既慢又容易漏，
而**发错钱、漏报社保的后果比多花半小时严重得多**。

**这个包做的事只有一件**：`--input <客户目录>`（每个子目录 = 一个客户 / 一套材料），
一次跑完所有客户，**每个客户一行结论**。

## 这个免费版查什么

下面 14 项，**每个客户都跑一遍**（检查项名字与引擎 `CHECKS_GIVEN` 逐条一致）：

1. 工资表发放前核对
2. 应付职工薪酬勾稽核对
3. 工资代发与银行回单核对
4. 代扣个税社保与申报核对
5. 个人所得税累计预扣核对
6. 社保缴纳明细核对
7. 社保缴费基数核对
8. 住房公积金缴存核对
9. 加班费核对
10. 计件工资核对
11. 年终奖与奖金池核对
12. 提成与底薪核对
13. 销售阶梯提成核对
14. 农民工工资专户核对

引擎里的 `CHECKS_WITHHELD`（本免费版**不执行**的项）会逐条打印出来，例如
「跨客户汇总台账」「薪酬与社保风险排序清单」「跨客户共性问题归类」「薪酬社保台账导出」——
**它们是"未执行的检查项"的说明文本，不是实现**。

另外，每个成员检查包**自己**没做的子检查（`SUB_CHECKS_WITHHELD`，本包合计 66 项）也在结果里
`scope.sub_checks_not_run` 如实列出 —— 两个档位都没实现它们，不会因为「买了完整档」就让买家以为这些项被跑了。

## 怎么用

```bash
node scripts/run.mjs --sample                  # 单客户样例（内置）
node scripts/run.mjs --sample-batch            # 3 个客户的批量样例（干净 / 有硬伤 / 没交材料）
node scripts/run.mjs --input 客户目录            # 批量：每个子目录 = 一个客户
node scripts/run.mjs --input 客户目录 --json     # 机器可读
```

客户目录怎么放（每个子目录里放该客户的一套薪酬社保材料，每项用 `=== 检查项 ===` 分段，Tab 分隔最稳）：

```
客户目录/
  豫州制造有限公司/薪酬社保材料.txt
  中岳建设有限公司/薪酬社保材料.txt
```

也可以把 14 张表拆成 14 个文件放进同一个子目录 —— 引擎会自己认表头找对应的那一项。
`templates/sample.json` 是引擎自己的样例，可以直接 `--input` 它先跑通一遍。

**退出码**：0 已执行检查 / 1 缺少入参 / 3 材料不足 / 4 入参读不到或无法解析 / 9 未预期错误。
**材料不足**（一个客户的材料都没有、材料为空或只有几行、认不出任何一张表）时，
本工具**不做任何认定、也不给任何结论**，打印缺什么并以退出码 3 结束 —— 不会把"没查"说成"通过"。

## 结论怎么读

- 每个客户一行：`[结论] 客户名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行`；
- 有价值的是**问题明细**：每条都带 `客户 + 检查项 + 来源文件:行号 + 类别 + 具体数字`，
  第三方可以拿同一份材料复算；
- 「工资表发放前核对」这一项，**成员包自带的样例本身**就是一份"有问题稿"（同一人两行、
  实发工资与合计行都对不上）。本包的 `--sample` 用的是**修好后的干净样例**（改完自证 0 条发现），
  想看它报问题请用 `--sample-batch`（第二个客户就是那种稿子）。

## 常见错法

- **把 14 项的材料全塞进一个文件却不分段**：引擎按 `=== 检查项 ===` 分段找每一项的表；
  不分段时只有第一段能被认出，其余 13 项会如实标成「未执行」并报一条「材料只覆盖了一部分」，
  不是"查过了没问题"。
- **一个客户一个目录**：`--input` 指向的目录里，**每个子目录 = 一个客户**。
  把所有客户的工资表放进同一个子目录，会被当成**一个**客户，跨客户的差异与汇总也就无从谈起。
- **以为「未执行」=「通过」**：某客户只交了 3 张表，那 3 项之外的 11 项是**没有核**，
  结论里写的是「未执行」，并且会单独报一条覆盖缺口。
- **把"含税"和"实发"两列混着填**：个税、社保、公积金这些代扣列必须单独成列，
  否则「实发工资 = 应发 − 各项扣款」这一条勾稽根本算不起来，该项会如实标「未执行」。
- **拿 `--sample` 的输出当自己的结论**：样例只是让你确认「跑得通、格式对」，
  真正的结论必须来自你自己的材料。


## 使用次数与完整档

本免费版每次运行结束后会向服务端做**一次匿名次数统计**：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），**不发送你的材料、不写任何文件**。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 统计不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 跨客户汇总台账（全部客户 × 全部 14 项检查合并成一张总表）
- 薪酬与社保风险排序清单（按 P0/P1/P2 排序，带客户名与原文文件行号）
- 跨客户共性问题归类（同一问题命中 2 个及以上客户时合并成一条共性项）
- 薪酬社保台账导出（Markdown 与 CSV 文本，直接用于发薪前复核说明）

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 边界（请务必知道）

- **不做**薪酬政策判断：某个人的工资该发多少、绩效怎么算、奖金怎么分，属于 HR 与用工管理判断，本工具不回答；
- **不判断**社保缴费基数、公积金缴存比例该按什么口径执行（各地政策不同，以当地经办机构口径为准）；
- **不代替审计**，也不出具鉴证意见或审计意见；**不核对**银行回单、社保申报回执、个税申报截图的真伪；
- **不读取**薪资系统 / 社保申报系统 / 银行代发系统的导出文件 —— 需要你先导出成文本，每个客户一个目录。
