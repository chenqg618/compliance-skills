# 政府补助与专项验收核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：财务、税务与项目申报岗，在**专项资金验收 / 补助结项 / 年度财政资金自查**这些固定节点上，
必须把这张对照表核一遍才能往下走 —— 补助资金对不上就结不了项，验收资料缺件就会被退件。

**这张表（政府补助台账与验收资料对照表）会逐项核对什么**：补助金额与到账金额的差额、专项支出合计与补助金额的配比、
验收资料清单的缺件、同一补助年度内的重复申报、支出超预算与补助比例失衡、关键字段缺失与金额为负。

每条结论都带**原文行号与出处**，可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么

**本免费版只做**台账金额与支出的**逐行复算与勾稽**（即表内算术与清单字面核对）；
**不做**补助资格认定，**不做**政策适用性判定，**不做**验收结论本身是否成立的判断。

范围就是下面这六项（跑 `--sample` 会打印实际执行了哪些）：

1. **补助到账金额与台账一致** —— 逐行复算 到账金额 − 补助金额，差额不为零即列出并给出差额。
2. **专项支出合计与补助金额配比** —— 专项支出合计须不小于补助金额，不足即报出缺口。
3. **验收资料清单完整性** —— 按 立项批复 / 验收报告 / 专项审计报告 / 支出明细台账 / 发票清单 逐件点名缺件。
4. **同一项目重复申报** —— 同一补助年度内 项目编号重复，或 项目名称+补助年度 重复。
5. **支出超预算与补助比例失衡** —— 专项支出合计 > 支出预算；补助金额 > 支出预算。
6. **关键字段缺失与金额为负** —— 关键字段空着或写成占位符、金额为负、金额看不懂（不会悄悄当成 0）。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看内置样例（一张干净表，应报 0 条问题）
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料
node scripts/run.mjs --input 你的材料.json --json
```

入参两种写法：

- `{"text": "（把表头和数据行一起贴进来，Tab 分隔最稳）"}`
- 直接把表（**含表头**）从 Excel 复制成文本存成文件，用 `--input` 指过去

退出码：`0` 已执行检查 / `1` 缺少入参 / `3` 材料不足（**不给结论**）/ `4` 入参读不到或无法解析 / `9` 未预期错误。

## 出参

`--json` 输出一份 JSON：

- `status` —— `success` 表示检查已执行；`insufficient_input` 表示材料不足，此时**没有结论**，`missing` 逐条列出还缺什么
- `result.findings[]` —— 每条含 `level`（P0/P1/P2）、`category`、`line`（**原文行号**）、`message`、`advice`
- `result.summary` —— 明细行数、问题条数、P0/P1/P2 计数，以及补助金额 / 到账金额 / 专项支出合计 / 支出预算的合计与到账差额
- `result.checks_executed` —— 本次**真的执行了**哪些检查
- `result.checks_not_run` —— 本次**没执行**哪些检查（如实列出，不会用默认值假装做过）
- `result.checks_out_of_scope` —— 本工具**根本不做**的判断
- `result.note` —— 零发现时出现，说明"通过"只覆盖上面写明的口径

## 常见错法（本产品专属）

1. **把「补助金额」当成「到账金额」填** —— 台账记的是批准金额，实际分期到账时两列必然不等，却常常只填一列。
   本工具把差额逐行列出来，让你自己判断是分期、代扣，还是登记错了。
2. **项目名称换一个字就当成新项目再报一次** —— 同一补助年度里同名项目出现两行，就是重复申报；
   分次到账应改「到账金额/累计到账」列，而不是新增行。
3. **验收资料清单写「见附件」或写「齐全」** —— 清单栏必须**逐件写到件名**，否则本工具一件都点不到，
   只能整栏报缺件；写成"齐全"这类结论词等于没写。
4. **专项支出合计漏了跨年报销与未到票的支出** —— 支出归集不全时，支出合计会小于补助金额，报出缺口。
5. **补助金额大于项目支出预算** —— 补助比例在算术上不成立，通常是预算列漏填了自筹部分，或补助金额串行登记。
6. **金额栏写"壹佰万元"或留成"待补"** —— 本工具只认数字、千分位、货币符号与括号负数；
   看不懂的值**不会当成 0**，会单独报「金额无法解析」。
7. **同一项目编号跨年度出现** —— 免费档**不**把它当重复申报（跨年续建是正常的），
   跨年度的归属口径核对不在本免费版范围内。

## 不包含什么

本免费版**不包含**下面这几类能力，也不会用默认值假装产出：

- 跨项目 / 跨年度汇总台账（按补助年度与验收结论分组的汇总）
- 差异归因（把差额归到 补助口径 / 支出归集 / 预算科目 / 跨年归属）
- 按差额金额排序的处理清单
- 同一补助文号被多个项目重复使用的检测

需要的请用完整档；`checks_not_run` 里会如实列出这些未执行项。

## 使用次数与完整档

本免费版会在**本包目录**里记一个使用次数（`scripts/.hint-count`，一个整数，不含任何机器或用户信息）。

· 前 3 次：**完全离线**（不发生任何网络请求），输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 第 4 次起才会向服务端问一次（只发包标识与次数），拿回完整档说明；
· 请求不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**；
· 不想要这次统计可以加 `--no-stats`（核对功能完全不受影响，只是拿不到完整档说明）。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。
