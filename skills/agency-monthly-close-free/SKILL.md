# 代账月结交付技能包（免费版）

> **完全本地运行**：批量壳与 7 个行业月度自查规则都打包在本技能里（`scripts/engine/`）。
> 不对外发材料、**不写任何文件**（结果只打到 stdout）、**没有次数上限**。

## 什么时候用

**谁会在什么时候用**：代账公司的会计/主管，在**每月月结交付之前**。一家代账公司手里有几十上百个客户，
每个客户每个月都要把同一批表核一遍；一个一个跑太慢，而且交付出问题时**说不清哪家客户哪一项没核**。

**这个工具做什么**：`--input 客户目录` 时，**目录里每个子目录就是一个客户**；本工具逐个客户跑
7 个行业月度自查包（每个包内部还有若干子检查项），最后**每个客户输出一行结论**：
客户名 / 7 个自查包各自「通过 / 有问题(几条) / 未执行」/ 问题条数与 P0、P1 计数。

每条问题都带**客户名 + 原文文件与行号**（例如 `月结材料.txt:5`），可被第三方用同一份材料复算；
某个客户没交材料时，**那个客户单独标「未执行」**，不会拖累其他客户，也**不会被算成"没问题"**；
只交了一部分材料时（只覆盖了部分自查包），会额外报一条 `P2 检查项未执行（材料只覆盖了一部分）`，
把"没核的那几项"点名列出——**绝不能因为跑了几个包就当成 7 个包都跑过了**。

## 这个免费版查什么（分层如实说明）

免费版是**完整可用的核心产出**——"一次跑完所有客户"这件事本身就在免费版里做完了：

- 免费版执行：`财务月度自查包`、`人力资源月度自查包`、`制造业月度自查包`、`建筑企业月度自查包`、
  `电商财务月度自查包`、`外贸月度自查包`、`集团财务月度自查包`（共 7 个包，逐客户全跑），
  外加批量壳自己的**覆盖缺口检查**（材料只覆盖一部分时明确报一条，见上）。
- 免费版**不包含**（完整档追加的那些项由引擎的 `CHECKS_WITHHELD` 如实列出，跑 `--sample` 会打印）：
  跨客户汇总台账、跨客户风险排序处理清单、跨客户共性问题归类、交付台账导出（Markdown / CSV）。
- ⚠️ **两个档位都不包含**：上面 7 个自查包**自己**声明未实现的检查项（例如财务包的「现金盘点差异」「发票领用存」）。
  它们在这 7 个上游免费包里就没实现，本包只是复用它们的规则，绝不会因为"另有完整档"就假装跑过。
  这些项在结果里叫 `scope.sub_checks_not_run`，**每个包各自列出**，一条都不藏。

## 怎么用

```bash
node scripts/run.mjs --sample                    # 单客户样例（内置，干净材料 → 0 条发现）
node scripts/run.mjs --sample-batch              # 3 个客户样例（干净 / 有一处硬伤 / 没交材料）
node scripts/run.mjs --input 客户目录             # 批量：每个子目录 = 一个客户
node scripts/run.mjs --input 客户目录 --json      # 机器可读
```

客户目录这样放（每个客户的标准表文本用 `=== 检查名 ===` 分段，Tab 分隔最稳）：

```text
客户目录/
  豫州商贸有限公司/月结材料.txt
  中岳建材有限公司/月结材料.txt
```

目录里没有子目录时，直接把每个文件当一个客户；`.json` 文件里若写 `{"text":"…"}` 就按 JSON 取正文。

## 规则是哪来的（复用，不是重写）

7 个行业月度自查包（含各自的子检查引擎）是**逐字节拷贝**进本技能包 `scripts/engine/parts/` 的，
本包只做"客户目录 → 逐客户跑 7 项 → 每个客户一行结论"的编排与汇总，**没有改写任何一条核对规则**。

## 常见错法（这个产品专属，逐条都真实踩过）

1. **`--input` 指到了"某个客户的文件"，却以为在跑批量**：`--input` 指向的应当是**客户目录**
   （里面每个子目录才是一个客户）。直接指一个客户的文件，就只会出 1 个客户的结果。
2. **把 `=== 检查名 ===` 分段行删掉了**：那 7 个自查包按分段名找自己的表；分段行没了，
   这些包会各自报「未执行」——**这是"未执行"，不是"通过"**，别当成核过了。
3. **一个客户的材料放进了另一个客户的目录**：结论会挂在**错的客户名下**。交付前扫一眼每行结论里的客户名
   与问题明细里的 `文件:行号`。
4. **把「未执行」读成「没问题」**：材料没交、分段缺失、表头认不出时，本工具**不给结论**，
   只标「未执行」。把「未执行」当通过，是这类批量工具最常见的翻车方式。
5. **用空格而不是 Tab 分隔列**：解析优先按 Tab，其次按"2 个及以上空格"。金额里带空格（如 `1 000.00`）
   会被拆成两列，凭空多出"关键字段缺失"。从 Excel 复制时用 Tab。
6. **合计行没写在第一列**：合计行要写在**身份列**（供应商 / 姓名 / 所属期 …）那一格为「合计 / 总计 / 小计」。
   写到别的列上不会被当成合计行，而是当成一条明细，于是"合计与明细之和不符"这种误报就出来了。
7. **指望它替你做账**：它只核表内/表间的算术与勾稽，**不判断账务处理是否合规**，也不出鉴证意见。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 跨客户汇总台账（全部客户 × 全部检查项合并成一张总表）
- 跨客户风险排序处理清单（按 P0/P1/未执行排序，带客户与原文定位）
- 跨客户共性问题归类（同一问题命中 2 个及以上客户时合并成一条共性项）
- 交付台账导出（Markdown 与 CSV 文本，直接用于月结交付说明）

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 使用次数与完整档

本免费版每次运行结束后会向服务端做**一次匿名次数统计**：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），**不发送你的材料、不写任何文件**。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 统计不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

## 边界（请务必知道）

本工具**不做**引擎 `CHECKS_OUT_OF_SCOPE` 里列的那些判断（代替做账、出鉴证意见、判断账务是否合规、
读 ERP/财务软件导出文件）；材料不足时**不给结论**（认不出表头就不出结论，绝不套用默认值）。
