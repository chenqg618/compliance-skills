# 土地增值税预缴与清算核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：房地产 / 建筑企业的**项目会计**，每次预缴申报与每一次清算都要做这张表；
月度预缴要算「预收收入 × 预征率」，清算时要一路算到「清算应补（退）」。
它是六步串行算术：

· 扣除项目合计 = 土地成本 + 开发成本 + 开发费用 + 税金
· 增值额 = 转让收入 − 扣除项目合计
· 增值率 = 增值额 ÷ 扣除项目合计
· 应纳土地增值税 = 增值额 × 档位税率 − 扣除项目合计 × 速算扣除系数
· 应预缴税额 = 预收收入 × 预征率
· 清算应补退 = 应纳土地增值税 − 已预缴税额

扣除项目漏计一项、增值率跨档时档位看错行（30% / 40% / 50% / 60% 与对应速算扣除系数），
差额就是几十上百万，也是税企争议最集中的一张表。行一多（多个项目、多个清算单位）人眼极易错。

**与已有能力的区别**：`property-tax-land-use-check` 核的是城镇土地使用税与房产税的计税依据；
`cit-prepay-check` 核的是企业所得税季度预缴。本技能核的是**土地增值税**这条独立的
预缴 / 清算链条（扣除项目 → 增值额 → 增值率 → 档位应纳税额 → 预缴 → 应补退）。

## 这个免费版查什么

· 扣除项目合计勾稽（土地成本 + 开发成本 + 开发费用 + 税金）

## 常见错法（这张表里真的会有人这么填）

1. **扣除项目漏一项**：只加土地成本 + 开发成本，把开发费用或税金落在表外；
   扣除项目合计一小，增值额与增值率立刻跨档，税额跟着错（复算会直接指出少了多少）。
2. **速算扣除系数乘错基数**：写成「增值额 × 速算扣除系数」；正确基数是**扣除项目合计**
   （应纳 = 增值额 × 档位税率 − 扣除项目合计 × 速算扣除系数）。
3. **增值率的分母用转让收入**：分母必须是扣除项目合计；分母一换，30% 的项目会被算进 40% 的档。
4. **拿全口径转让收入算预缴**：预缴口径是「**预收收入** × 预征率」，
   预收收入按实际收到（含定金、首付、按揭到账）确认，不能整盘收入一起乘。
5. **已预缴只填一个总数**：预缴是逐期申报缴的，某一期预收收入漏报或预征率用错，
   累计数就对不上；差异要能落到具体期次。
6. **档位税率与速算扣除系数不成对**：同一档位里混用了两个系数（例如 40% 档一会儿 5%、一会儿 10%），
   或者把税率与系数写反 —— 算出来的税额会成负的。
7. **缺格用 0 顶、负号照抄**：土地成本、已预缴税额空着就当 0 算，或者粘贴时把减号带进来；
   本工具不会替你填，会直接报「关键字段缺失」或「按口径不应为负」。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 增值率档位与表内档位税率/速算扣除系数不匹配判定
- 扣除项目口径与表内多数项目不一致判定
- 预征率与约定（或表内多数项目）不符判定
- 清算单位划分重复或遗漏判定

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 使用次数与完整档

本免费版每次运行结束后会向服务端做**一次匿名次数统计**：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），**不发送你的材料、不写任何文件**。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 统计不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

## 边界（请务必知道）

本工具**不做**引擎 `CHECKS_OUT_OF_SCOPE` 里列的那些判断：不判断某项支出能不能计入扣除项目、
不套用某个地区的预征率或普通住宅优惠、不给税务意见、不做清算筹划、不读 .xlsx。
档位税率、速算扣除系数与预征率**一律取自你表里的值或入参**，本工具只做口径一致的算术与表内一致性判定；
材料不足时**不给结论**，也不会输出「未发现问题」。
