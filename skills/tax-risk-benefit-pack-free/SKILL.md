# 税费自查与优惠技能包（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`scripts/engine/`）。
> 不联网、不需要 API Key、**没有调用次数上限**、**不写任何文件**，材料不出本机。

## 什么时候用

**中小企业税务会计 / 代账公司的涉税岗**，在**每次申报之后、税务自查与汇算之前**。

典型场景：月度/季度复核前，把一类检查一次跑完所有客户

## 这个免费版查什么

**一次跑完所有客户，每家客户一行结论**（免费版的核心产出，完整可用）：

1. **增值税税负率与行业预警核对** —— 复用 `parts/vat-burden-check/`（逐字节来自免费包 `vat-burden-check-free`）
2. **增值税申报表与账面收入比对** —— 复用 `parts/vat-filing-reconcile/`（逐字节来自免费包 `vat-filing-reconcile-free`）
3. **税务风险指标异常项核对** —— 复用 `parts/tax-risk-indicator-check/`（逐字节来自免费包 `tax-risk-indicator-check-free`）
4. **税收优惠资格适用条件核对** —— 复用 `parts/tax-incentive-eligibility-check/`（逐字节来自免费包 `tax-incentive-eligibility-check-free`）
5. **税收滞纳金与罚款核对** —— 复用 `parts/late-fee-check/`（逐字节来自免费包 `late-fee-check-free`）

> 每一项的实际规则在 `scripts/engine/parts/<检查项>/` 里（**逐字节复用**仓库里已有的免费引擎，
> 一行规则都没有改）。本包只做"目录 → 客户 → 逐项派发"的编排。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 单客户样例（内置，5 项全跑）
node scripts/run.mjs --sample-batch           # 3 家客户的批量样例（干净 / 有硬伤 / 未交材料）
node scripts/run.mjs --input <客户目录>     # 批量：每个子目录 = 一家客户
node scripts/run.mjs --input <材料.json>        # 单客户：JSON 或纯文本
```

客户目录怎么放（每个子目录里放这家客户的一套材料，每项用 `=== 检查项 ===` 分段，Tab 分隔最稳）：

```
客户目录/
  豫州商贸有限公司（2026-02 申报后自查）/税费材料.txt
  中岳建材有限公司（2026-02 申报后自查）/税费材料.txt
```

## 结论怎么读

- 每家客户一行：`[结论] 客户名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行`；
- 有价值的是**问题明细**：每条都带 `客户 + 检查项 + 来源文件:行号 + 类别 + 具体数字`；
- 「未执行」与「通过」是两件事：**没交材料 / 材料认不出表 = 未执行**，不是"没问题"。

## 常见错法

- **把几家客户的材料放进同一个子目录**：`--input` 指向的目录里，**每个子目录 = 一家客户**。混在一起时引擎只能按表头认出哪张表属于哪一项，**认不出客户归属**，结论就没有客户名。
- **把 5 项的材料全塞进一个文件却不分段**：引擎按 `=== 检查项 ===` 分段找每一项的表；不分段时除了第一项，其余四项都会落进「未执行」，看起来"没问题"其实是没核。
- **以为「未执行」=「通过」**：某个客户只交了 2 张表，那 2 项之外的是**没有核**，结论里会单列「未执行」，**不要**把它当成"这家没问题"。
- **拿税负率预警阈值当结论**：行业预警值只是**提示比较**，是不是异常要结合你的业务结构判断；本工具只保证"你填的数和算式对得上"，**不给税务意见**。
- **拿 `--sample` 的输出当自己的结论**：样例只是让你确认"跑得通、格式对"，里面的数字是虚构的，**必须换成你自己的材料**再跑。
