# 电商与平台结算技能包（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`scripts/engine/`）。
> 不联网、不需要 API Key、**没有调用次数上限**、**不写任何文件**。

## 什么时候用

**谁会在什么时候用**：在电商平台卖货的商家、连锁/加盟品牌、商场联营专柜、餐饮门店，
以及做直播、OTA、会员与促销的运营与财务岗，在**每个结算周期对账之前**。
结算从来不是一张单：电商平台结算核对、退货退款与货款结算核对、平台账期与在途资金核对、
直播佣金与坑位费结算核对、OTA 佣金与净结算核对、商场联营抽成与保底核对、
加盟抽成与最低保底核对、连锁加盟门店结算核对、会员积分与储值卡核销核对、
促销补贴与核销核对、采购返利与阶梯核算核对、整车厂返利与商务政策核对、
寄售代销结算核对、餐饮门店日营业款核对 —— 每一份都有自己的勾稽关系，逐份手核既慢又容易漏，
而**平台少结的那部分就是真金白银**。

**这个包做的事只有一件**：`--input <客户目录>`（每个子目录 = 一个客户 / 一套材料），
一次跑完所有客户，**每个客户一行结论**。

## 这个免费版查什么

下面 14 项，**每个客户都跑一遍**（检查项名字与引擎 `CHECKS_GIVEN` 逐条一致）：

1. 电商平台结算核对
2. 退货退款与货款结算核对
3. 平台账期与在途资金核对
4. 直播佣金与坑位费结算核对
5. OTA佣金与净结算核对
6. 商场联营抽成与保底核对
7. 加盟抽成与最低保底核对
8. 连锁加盟门店结算核对
9. 会员积分与储值卡核销核对
10. 促销补贴与核销核对
11. 采购返利与阶梯核算核对
12. 整车厂返利与商务政策核对
13. 寄售代销结算核对
14. 餐饮门店日营业款核对

引擎里的 `CHECKS_WITHHELD`（本免费版**不执行**的项）会逐条打印出来，例如
「跨客户汇总台账」「结算差异风险排序清单」「跨客户共性问题归类」「电商与平台结算台账导出」——
**它们是"未执行的检查项"的说明文本，不是实现**。

另外，每个成员检查包**自己**没做的子检查（`SUB_CHECKS_WITHHELD`，本包合计 68 项）也在结果里
`scope.sub_checks_not_run` 如实列出 —— 两个档位都没实现它们，不会因为「买了完整档」就让买家以为这些项被跑了。

## 怎么用

```bash
node scripts/run.mjs --sample                  # 单客户样例（内置）
node scripts/run.mjs --sample-batch            # 3 个客户的批量样例（干净 / 有硬伤 / 没交材料）
node scripts/run.mjs --input 客户目录            # 批量：每个子目录 = 一个客户
node scripts/run.mjs --input 客户目录 --json     # 机器可读
```

客户目录怎么放（每个子目录里放该客户的一套结算材料，每项用 `=== 检查项 ===` 分段，Tab 分隔最稳）：

```
客户目录/
  豫州电商旗舰店/电商与平台结算材料.txt
  中岳百货联营专柜/电商与平台结算材料.txt
```

也可以把 14 张表拆成 14 个文件放进同一个子目录 —— 引擎会自己认表头找对应的那一项。
`templates/sample.json` 是引擎自己的样例，可以直接 `--input` 它先跑通一遍。

**退出码**：0 已执行检查 / 1 缺少入参 / 3 材料不足 / 4 入参读不到或无法解析 / 9 未预期错误。
**材料不足**（一个客户的材料都没有、材料为空或只有几行、认不出任何一张表）时，
本工具**不做任何认定、也不给任何结论**，打印缺什么并以退出码 3 结束 —— 不会把"没查"说成"通过"。

## 结论怎么读

- 每个客户一行：`[结论] 客户名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行`；
- 有价值的是**问题明细**：每条都带 `客户 + 检查项 + 来源文件:行号 + 类别 + 具体数字`，
  第三方可以拿同一份材料复算；
- 行号口径与本包无关：成员引擎的"第几行"各不相同，本包**以原文内容为准重新落位** ——
  用该条结论里的原文片段回到你交的那份材料里核对，一定对得上同一行；
- 本包的 `--sample` 用的是 14 份成员样例拼起来的**干净稿**（各自自证 0 条发现），
  想看它怎么报问题请用 `--sample-batch`（第二个客户就是那种"有硬伤"的稿子）。

## 常见错法

- **一个客户一个目录**：`--input` 指向的目录里，**每个子目录 = 一个客户**。
  把所有客户的结算单放进同一个子目录，会被当成**一个**客户，跨客户的差异与汇总也就无从谈起。
- **把 14 项的材料全塞进一个文件却不分段**：引擎按 `=== 检查项 ===` 分段找每一项的表；
  不分段时只有第一段能被认出，其余 13 项会如实标成「未执行」并报一条「材料只覆盖了一部分」，
  不是"查过了没问题"。
- **以为「未执行」=「通过」**：某客户只交了 3 张表，那 3 项之外的 11 项是**没有核**，
  结论里写的是「未执行」，并且会单独报一条覆盖缺口。
- **把平台补贴 / 活动扣款 / 保证金扣除混在"佣金"里**：这些列必须单独成列，
  否则「销售额 − 佣金 − 服务费 − 运费 − 退款 = 结算金额」这一条勾稽根本算不起来，该项会如实标「未执行」。
- **拿 `--sample` 的输出当自己的结论**：样例只是让你确认「跑得通、格式对」，
  真正的结论必须来自你自己的材料。
