# 合同履约成本与收入配比核对（免费）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：**建造/软件/服务类公司的项目财务与收入会计**，在**月度（或按履约进度）确认收入与成本、以及审计交底稿之前**：

- 本期确认收入 = 合同总金额 × 履约进度 − 上期累计已确认收入；
- 累计已确认收入不得超过合同总金额；
- 累计履约成本 ÷ 累计收入 与 预计总成本 ÷ 合同总金额 应当同向（配比）。

## 这个免费版查什么

1. **合计行逐列复核**（合同总金额 / 累计收入 / 本期收入 / 累计成本 / 本期成本 / 已开票 / 已收款）；
2. **本期确认收入与履约进度吻合**（按进度应确认累计 − 上期累计，P0）；
3. **累计已确认收入不超过合同总金额**（P0）；
4. **成本收入配比**（成本率与合同预计成本率偏离 > 10% 提示）；
5. **已收款 / 已开票不超过合同总金额**（P1）；
6. **同一合同编号重复行**检测；
7. **空白与占位符**检测（含必需列缺失）。

## 常见错法（这些表里真的会有人这么填）

1. **把"已开票金额"当"已确认收入"**：开票是税务/结算口径，收入按履约进度确认，两者在时点上不同，混填会让进度校验全错。
2. **履约进度填"已发生成本 ÷ 预计总成本"却与收入进度口径不一致**：投入法/产出法要选一种并前后一致，混用会让本期收入忽高忽低。
3. **本期确认收入按"合同总金额 × 本期进度"直接算**：必须减去**上期累计已确认收入**，否则累计会重复计入。
4. **累计履约成本超过预计总成本却不调整**：超支要重新估计总成本并修正进度，否则配比校验会持续报。
5. **同一合同按批次分多行**：会报重复行；请合并成一行或在备注里注明批次与对应进度。


## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 履约进度为 0 或 100% 但本期仍有确认收入 / 成本提示
- 履约进度不在 0 ~ 100% 区间检测
- 累计履约成本超过合同预计总成本检测
- 已收款超过已开票 110% 提示（先收款后开票本身正常）
- 累计已确认收入与「合同总金额 × 履约进度」差异超 1% 检测

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 使用次数与完整档

本免费版每次运行结束后会向服务端做**一次匿名次数统计**：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），**不发送你的材料、不写任何文件**。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 统计不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

## 边界（请务必知道）

- **不做**会计判断：履约进度该用投入法还是产出法、是否属于在某一时段内履约，请按准则与业务实质判断；
- **不代替**收入审计程序或出具鉴证意见，也不判断合同变更/索赔的处理；
- **不核对**合同、发票、验收单的**真伪**，也不与项目管理系统逐行比对；
- **不读取**项目管理系统 / 合同系统 / 财务系统的导出文件——需要你先导出成文本贴进来；
- **不判断**收入与成本的税务处理（属于税务判断）。
