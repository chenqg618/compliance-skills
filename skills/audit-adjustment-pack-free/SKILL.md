# 审计与账务调整技能包（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`scripts/engine/`）。
> 不联网、不需要 API Key、**没有调用次数上限**、**不写任何文件**。

## 什么时候用

**谁会在什么时候用**：会计师事务所的审计助理 / 项目经理，以及企业财务的报表编制与复核岗，
在**年度审计与专项审计的"调整分录汇总、报表项目复核"**这些固定节点上。
审计与账务调整底稿从来不是一张表：试算平衡、审计调整分录、资产减值准备、资产处置损益、
固定资产折旧、无形资产摊销、模具摊销、坏账准备、预提费用、预付款核销、长期待摊费用摊销、
存货跌价准备、现金盘点长短款、罚款与违约金结算 ——
每一张都有自己的勾稽关系，逐张手核既慢又容易漏，而且**每个被审计单位、每一期都要重复一遍**；
**调整分录借贷不平、减值或折旧算错、盘亏挂账不处理，后果比多花半小时严重得多**。

**这个包做的事只有一件**：`--input <单位目录>`（每个子目录 = 一个被审计单位 / 一套底稿），
一次跑完所有单位，**每个被审计单位一行结论**。

## 这个免费版查什么

下面 14 项，**每个被审计单位都跑一遍**（检查项名字与引擎 `CHECKS_GIVEN` 逐条一致）：

1. 试算平衡与科目余额核对
2. 审计调整分录核对
3. 资产减值准备核对
4. 资产处置损益核对
5. 固定资产折旧核对
6. 无形资产摊销核对
7. 模具摊销核对
8. 坏账准备计提核对
9. 预提费用核对
10. 预付款与预付账款核销核对
11. 长期待摊费用摊销核对
12. 存货跌价准备核对
13. 现金盘点与长短款核对
14. 罚款与违约金结算核对

引擎里的 `CHECKS_WITHHELD`（本免费版**不执行**的项）会逐条打印出来，例如
「跨被审计单位汇总台账」「账务调整风险排序清单」「跨单位共性问题归类」「审计调整台账导出」——
**它们是"未执行的检查项"的说明文本，不是实现**。

另外，每个成员检查包**自己**没做的子检查（`SUB_CHECKS_WITHHELD`，本包合计 69 项）也在结果里
`scope.sub_checks_not_run` 如实列出 —— 两个档位都没实现它们，不会因为「买了完整档」就让使用者以为这些项被跑了。

## 怎么用

```bash
node scripts/run.mjs --sample                  # 单单位样例（内置）
node scripts/run.mjs --sample-batch            # 3 个被审计单位的批量样例（干净 / 有硬伤 / 没交材料）
node scripts/run.mjs --input 单位目录           # 批量：每个子目录 = 一个被审计单位
node scripts/run.mjs --input 单位目录 --json    # 机器可读
```

单位目录怎么放（每个子目录里放该单位的一套审计调整底稿，每项用 `=== 检查项 ===` 分段，Tab 分隔最稳）：

```
单位目录/
  豫州制造有限公司/审计调整底稿.txt
  中岳建设有限公司/审计调整底稿.txt
```

也可以把 14 张表拆成 14 个文件放进同一个子目录 —— 引擎会自己认表头找对应的那一项；
分段名写成检查项名（如 `=== 固定资产折旧核对 ===`）时，引擎**优先**把这一段喂给同名的那一项，
避免几张底稿列名相近时派发错位。
`templates/sample.json` 是引擎自己的样例，可以直接 `--input` 它先跑通一遍。

**退出码**：0 已执行检查 / 1 缺少入参 / 3 材料不足 / 4 入参读不到或无法解析 / 9 未预期错误。
**材料不足**（一个单位的材料都没有、材料为空或只有几行、认不出任何一张表）时，
本工具**不做任何认定、也不给任何结论**，打印缺什么并以退出码 3 结束 —— 不会把"没查"说成"通过"。

## 结论怎么读

- 每个被审计单位一行：`[结论] 单位名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行`；
- 有价值的是**问题明细**：每条都带 `被审计单位 + 检查项 + 来源文件:行号 + 类别 + 具体数字`，
  第三方可以拿同一份底稿复算；
- 行号一律**以你的原文内容为准落位**（成员引擎内部的行号口径不统一，本包只按"这一行在原文里真的存在"
  来定位），所以拿行号回原文一定找得到那一行。

## 常见错法

- **把 14 项的表全塞进一个文件却不分段**：引擎按 `=== 检查项 ===` 分段找每一项的表；
  不分段时只有第一段能被认出，其余 13 项会如实标成「未执行」并报一条「材料只覆盖了一部分」，
  不是"查过了没问题"。
- **一个被审计单位一个目录**：`--input` 指向的目录里，**每个子目录 = 一个被审计单位**。
  把所有单位的底稿放进同一个子目录，会被当成**一个**单位，跨单位的差异与汇总也就无从谈起。
- **以为「未执行」=「通过」**：某单位只交了 3 张表，那 3 项之外的 11 项是**没有核**，
  结论里写的是「未执行」，并且会单独报一条覆盖缺口。
- **几张底稿列名相近就混着放**：处置损益表里也有「原值 / 累计折旧 / 账面净值」，折旧那一项会"认得上"它。
  本包的做法是**先认段名、再认内容**（`=== 固定资产折旧核对 ===` 这一段优先喂给折旧那一项），
  所以分段名请照抄检查项名，别写成「附表一」「Sheet2」。
- **拿 `--sample` 的输出当自己的结论**：样例只是让你确认「跑得通、格式对」，
  真正的结论必须来自你自己的底稿。
