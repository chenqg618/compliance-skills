# 废料边角料销售与回收结算核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 不联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：制造业与建筑业里，**财务（成本/总账会计）每月结账时必须核一遍废料台账，
每年审计时还要再核一遍**。因为废料（边角料、废钢、铜屑、铝屑、废纸、废木料）卖出去是一笔收入，
而它长期是"**账外资金**"的高发区：过磅数对不上、扣杂率被抬高、单价低于合同价、收入不入账 ——
审计与内控就盯这几项。回收商给的结算单和自家台账放在一起，**这几件事都能算出来对错**：

- 结算数量 = 过磅净重 − 扣杂量 − 水分扣量
- 结算金额 = 结算数量 × 结算单价
- 台账废料收入 = 结算金额
- 上期结存 + 本期产出 − 本期出库 = 期末结存

纯算术，但料别一多、单据一多，人眼极易错；而算错的每一分钱都是从自己口袋里漏出去的。

## 这个免费版查什么

引擎逐条执行下面这 8 项（**本版本不执行的检查项会如实列在结果的 `scope.checks_not_run` 里**）：

1. **结算数量勾稽复算**：结算数量 = 过磅净重 − 扣杂量 − 水分扣量
2. **结算金额勾稽复算**：结算金额 = 结算数量 × 结算单价
3. **废料收入与台账勾稽**：逐行比对 结算金额 与 台账废料收入
4. **结存数量勾稽复算**：上期结存 + 本期产出 − 本期出库 = 期末结存
5. **合计行逐列复核**：每一列的合计是否等于各行之和
6. **重复过磅单号检测**：同一张磅单只应结算一次
7. **关键字段空缺与占位符检测**（结算单号允许为空，那是完整档要抓的异常）
8. **数量与金额为负检测**

每条结论都带**原文行号与出处**（如「第 3 行（期间 2026-06／类别 废钢／过磅单号 WB-2606-001）」），
可被第三方用同一份输入复算；**材料不足时不给结论**，会明确列出还缺什么。

## 和已有的核对有什么不同

- `生产投入产出与报废率核对` 核的是**车间里料去哪了**（投入量/完工量/报废量/良率）；
- `废料报废审批核对` 核的是**报废审批权限与流程**；
- 本能力核的是**废料卖出以后与回收商的结算**：过了磅、扣了杂、定了价，**钱算得对不对、收够了没有**。

## 常见错法（这张台账里真的会有人这么填）

1. **拿过磅净重当结算数量**：忘了先减扣杂再减水分扣量（或只减了一样），结算数量就多算了，
   金额跟着一起错 —— 这是回收商最希望你看错的地方。
2. **含税价与不含税价混用**：合同价是不含税、结算单上是含税（或反之），单价那一列两种口径混着填；
   本工具只按你填的口径重算，**口径请先统一成一种**，否则差额算不准。
3. **扣杂量当"扣杂率"填**：填进去的是 3（表示 3%），而本工具按**重量**读；上限列才是百分数（写 `3%`）。
   一格填错，后面所有勾稽都跟着错。
4. **期末结存倒着填**：为了让结存好看，先写期末结存再倒推本期出库，
   于是"上期结存 + 本期产出 − 本期出库 = 期末结存"这条恒等式被打破 —— 工具会直接点出来。
5. **同一张磅单分两行录**（一行过磅、一行结算），或月结时把上月的磅单再录一次：
   重复过磅单号会让出库量与收入一起翻倍，也常是重复付款的来源。
6. **合计行忘了跟着更新**：明细加了单、合计行还是上个月的数；合计行正是给管理层和审计看的那一行。
7. **出库有量、结算单号留空**：免费版会提示结算单号为空属正常（那是完整档要抓的"可能未入账"），
   所以**不要**用空白去"绕过"检查：这笔收入的去向必须在完整档里查清楚。
