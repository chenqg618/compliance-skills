# 工程与项目结算技能包（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`scripts/engine/`）。
> 不联网、不需要 API Key、**没有调用次数上限**、**不写任何文件**。

## 什么时候用

**谁会在什么时候用**：工程公司的项目会计、成本岗，以及代建方 / 业主方的工程管理岗，
在**每期计量报量、分包结算、开票回款、竣工转固**这些固定节点上。
工程结算底稿从来不是一张表：本期产值与计量、进度款与质保金扣留、质保金退还、项目开票与回款、
挣值（EVM）、在建工程转固与利息资本化、维修资金专项付款、分包结算、预付款冲抵、
违约金与索赔结算、安全生产费提取使用、投标保证金收退、软件外包里程碑付款 ——
每一张都有自己的勾稽关系，逐张手核既慢又容易漏，而且**每个项目、每一期都要重复一遍**；
**少扣一笔质保金、多付一笔进度款、转固金额算错，后果比多花半小时严重得多**。

**这个包做的事只有一件**：`--input <项目目录>`（每个子目录 = 一个项目 / 一套材料），
一次跑完所有项目，**每个项目一行结论**。

## 这个免费版查什么

下面 14 项，**每个项目都跑一遍**（检查项名字与引擎 `CHECKS_GIVEN` 逐条一致）：

1. 工程产值与进度确认核对
2. 工程进度款与质保金核算核对
3. 工程质量保证金扣留与退还核对
4. 项目开票与回款核对
5. 项目挣值分析（EVM）核对
6. 在建工程转固与利息资本化核对
7. 在建工程转固核对
8. 维修资金与专项工程付款核对
9. 分包结算与产值核对
10. 预付款与预付账款核销核对
11. 罚款与违约金结算核对
12. 安全生产费用提取与使用核对
13. 投标保证金收退核对
14. 软件外包里程碑验收与付款核对

引擎里的 `CHECKS_WITHHELD`（本免费版**不执行**的项）会逐条打印出来，例如
「跨项目汇总台账」「结算风险排序清单」「跨项目共性问题归类」「结算台账导出」——
**它们是"未执行的检查项"的说明文本，不是实现**。

另外，每个成员检查包**自己**没做的子检查（`SUB_CHECKS_WITHHELD`，本包合计 71 项）也在结果里
`scope.sub_checks_not_run` 如实列出 —— 两个档位都没实现它们，不会因为「买了完整档」就让买家以为这些项被跑了。

## 怎么用

```bash
node scripts/run.mjs --sample                  # 单项目样例（内置）
node scripts/run.mjs --sample-batch            # 3 个项目的批量样例（干净 / 有硬伤 / 没交材料）
node scripts/run.mjs --input 项目目录           # 批量：每个子目录 = 一个项目
node scripts/run.mjs --input 项目目录 --json    # 机器可读
```

项目目录怎么放（每个子目录里放该项目的一套工程结算材料，每项用 `=== 检查项 ===` 分段，Tab 分隔最稳）：

```
项目目录/
  滨江路改造工程/工程结算材料.txt
  城东安置房项目/工程结算材料.txt
```

也可以把 14 张表拆成 14 个文件放进同一个子目录 —— 引擎会自己认表头找对应的那一项。
`templates/sample.json` 是引擎自己的样例，可以直接 `--input` 它先跑通一遍。

**退出码**：0 已执行检查 / 1 缺少入参 / 3 材料不足 / 4 入参读不到或无法解析 / 9 未预期错误。
**材料不足**（一个项目的材料都没有、材料为空或只有几行、认不出任何一张表）时，
本工具**不做任何认定、也不给任何结论**，打印缺什么并以退出码 3 结束 —— 不会把"没查"说成"通过"。

## 结论怎么读

- 每个项目一行：`[结论] 项目名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行`；
- 有价值的是**问题明细**：每条都带 `项目 + 检查项 + 来源文件:行号 + 类别 + 具体数字`，
  第三方可以拿同一份材料复算；
- 行号一律**以你的原文内容为准落位**（成员引擎内部的行号口径不统一，本包只按"这一行在原文里真的存在"
  来定位），所以拿行号回原文一定找得到那一行。

## 常见错法

- **把 14 项的材料全塞进一个文件却不分段**：引擎按 `=== 检查项 ===` 分段找每一项的表；
  不分段时只有第一段能被认出，其余 13 项会如实标成「未执行」并报一条「材料只覆盖了一部分」，
  不是"查过了没问题"。
- **一个项目一个目录**：`--input` 指向的目录里，**每个子目录 = 一个项目**。
  把所有项目的结算表放进同一个子目录，会被当成**一个**项目，跨项目的差异与汇总也就无从谈起。
- **以为「未执行」=「通过」**：某项目只交了 3 张表，那 3 项之外的 11 项是**没有核**，
  结论里写的是「未执行」，并且会单独报一条覆盖缺口。
- **把"上期累计"和"本期发生"两列混着填**：进度款、质保金、转固金额这些勾稽都要用到
  "期初 + 本期 − 本期支出 = 期末"这类滚动关系，缺一列该项就会如实标「未执行」。
- **拿 `--sample` 的输出当自己的结论**：样例只是让你确认「跑得通、格式对」，
  真正的结论必须来自你自己的材料。
