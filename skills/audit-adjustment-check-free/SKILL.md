# 审计调整分录核对（免费）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：**年审期间**，审计师把调整分录建议（审计调整）交过来，
财务要在这张**审计调整分录核对表**上逐条落实、并与审计师来回核对清楚 —— 调错一行，报表就是错的。

**这张表会逐项核对什么**：一张表里每一行 = 一条调整分录的一个科目（借方或贷方一侧）。
本工具把表里能**算出来的东西**全部复算一遍：

1. 借贷差额复算（借贷差额 = 借方合计 − 贷方合计，必须为 0）
2. 科目净影响复算（借方金额 − 贷方金额 = 科目净影响）
3. 合计行逐列复核（合计行 = 各明细行逐列相加）
4. 同一调整事项重复行检测（整行重复粘贴 = 调整被算两次）
5. 空白与占位符检测（编号/科目名称空着、借贷两列都没填、金额列写着"待填"）
6. 金额为负检测（红字冲销请单独列示，别与正常分录混在一起）

（检查项的权威清单在引擎的 `CHECKS_GIVEN` / `CHECKS_WITHHELD` 里，跑 `--sample` 会打印实际执行了哪些。）

每条结论都带**原文行号与出处**（`line` 就是表里的第几行），可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么（例如缺「借方金额」这一列）。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看样例
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料
```

入参写法：`{"text": "（把你那张表的**表头**和若干行一起复制进来，Tab 分隔最稳）"}`；
也可以直接把核对表从 Excel 复制成文本存成文件传给 `--input`。

## 常见错法（这张表里真的会有人这么填）

1. **借贷两边抄得不平**：调整分录的借贷必须相等。少抄一行、方向写反、小数位看错，都靠"借方合计 − 贷方合计"当场暴露；同一笔调整的这两边**必须写同一个调整事项编号**，否则连"是不是同一笔"都判不出来。
2. **「科目净影响」按余额方向填反**：净影响 = **借方 − 贷方**（贷方一侧是负数），不是"增加为正"。这是报表科目串位最常见的来源。
3. **同一笔调整拆成多行却不写编号 / 不写说明**：编号是把它与审计师的调整建议、底稿对上的钥匙；说明是判断"影响科目与金额是否与调整事项一致"的唯一依据。
4. **整行复制粘贴导致重复调整**：一行重复 = 调整被算两次。本工具按"事项 + 科目 + 借贷金额 + 净影响 + 说明"整行比对。
5. **合计行手改**：手改过的合计行与明细对不上；本工具会逐列复算合计行（借贷金额、科目净影响）。

## 使用次数与完整档

本免费版每次运行结束后会向服务端做**一次匿名次数统计**：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），**不发送你的材料、不写任何文件**。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 统计不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 借贷不平超过容差提示
- 调整事项缺说明或编号提示
- 同一科目同一事项重复调整提示
- 调整金额超过参考重要性水平提示（参考口径）
- 调整后科目方向异常（资产类为负）提示

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 边界（请务必知道）

本工具**不做**引擎 `CHECKS_OUT_OF_SCOPE` 里列的那些判断 —— 例如"这笔调整的会计处理对不对""科目用得对不对""要不要调、要不要披露"，
以及**重要性水平、会计政策与科目方向**（以审计计划、企业会计准则与审计师意见为准）。
它只核**内部勾稽**：借贷差额、科目净影响、合计行、重复、空白、负数。
材料不足时**不给结论**，也不会输出「未发现问题」。
