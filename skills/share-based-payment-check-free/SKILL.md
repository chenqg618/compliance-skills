# 股份支付费用分摊核对（免费）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：有股权激励（限制性股票 / 股票期权 / 员工持股平台份额）的公司，
财务在**每月（或每季）确认股份支付费用、以及给审计/券商交底稿之前**，必须把这几列核一遍：

- 授予总额 = 授予数量 × 授予日公允价值；
- 直线法每期 = 授予总额 ÷ 等待期月数；
- 期末未分摊余额 = 期初未分摊余额 − 本期实摊金额；
- 期末未分摊余额 = 授予总额 − 累计已分摊金额；累计已分摊 **不许超过**授予总额。

审计和券商盯的就是这几列能不能**滚动对上**；对不上就是底稿返工，而这类错误**全都能算出来对错**。

## 这个免费版查什么

1. **合计行逐列复核**：合计 = 明细逐行相加（数量 / 期初 / 应分摊 / 实摊 / 累计 / 期末）；
2. **期末 = 期初 − 本期实摊**（滚动关系，最常错的一条）；
3. **期末 = 授予总额 − 累计已分摊**（总额关系）；
4. **本期实摊为负**检测；
5. **同一计划同一期间重复行**检测；
6. **空白与占位符**检测（含必需列缺失）。

## 常见错法（这张表里真的会有人这么填）

1. **等待期月数写成"年数"**：等待期 2 年要填 **24**；填 2 会让直线法每期金额差 12 倍。
2. **授予数量单位混用**：万股与股混填（100 万股 vs 100 股）会让授予总额差 10000 倍；一张表里必须同一口径。
3. **只改本期实摊、忘了改期末余额**：这正是本工具第一条滚动校验要抓的——三条关系里错一条就会被报出来。
4. **把等待期已经结束的计划继续分摊**：等待期已满（已过月数 > 等待期月数）就该停止分摊、余额归零；
   完整档会专门点这一条（免费档只核滚动关系，不判断等待期是否到期）。
5. **同一计划分两次粘贴却都写同一期间**：会报重复行；如果确实分两批授予，请把"授予日"或"已过月数"区分开。


## 使用次数与完整档

本免费版每次运行结束后会向服务端做**一次匿名次数统计**：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），**不发送你的材料、不写任何文件**。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 统计不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 本期实摊与直线法口径（授予总额 ÷ 等待期月数）偏离超过 5% 提示
- 累计已分摊超过授予总额（超额分摊）检测
- 已过月数超过等待期月数却仍在分摊（等待期已满）检测
- 等待期已满但期末未分摊余额未归零提示
- 累计已分摊 + 期末未分摊 ≠ 授予总额 检测

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 边界（请务必知道）

- **不做**会计判断：授予日公允价值该用市价、评估价还是期权定价模型的结果，等待期与业绩条件怎么定，
  能不能一次确认——这些由公司会计政策与评估/审计决定，本工具只核你给的表内数字与勾稽关系；
- **不代替**审计程序，也不出具鉴证意见；
- **不判断**要不要确认递延所得税，或股份支付能否税前扣除；
- **不读取**股权激励管理系统 / 券商底稿 / 评估报告的原始文件——需要你先导出成文本贴进来；
- 材料不足（认不出表头、没有数据行、必需列缺失）时**不给结论**，只告诉你还缺什么。
