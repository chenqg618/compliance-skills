# 证照与特种设备年检到期台账核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（engine/ 目录）。
> 不联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：制造 / 物业 / 建筑 / 物流企业的安全环保管理员、设备管理员与行政，
在**每月的合规检查**与**年度审计**这两个固定节点上，都要把证照与特种设备台账核一遍才能往下走；
核对结果直接决定这个月哪几台设备要送检、哪几张证照要续期。**证照或特种设备逾期未检 =
罚款甚至停产**，所以这不是"有空再看"的事，是每月必做。

**这张台账会逐项核对什么**（免费版执行的 7 项）：

- 有效期至 = 上次检验日期 + 检验周期（月，日对齐、月末夹取）
- 距到期天数 = 有效期至 − 基准日（**基准日取台账内最新日期，不取系统当天**）
- 状态与到期情况是否一致（写「有效」却已过期 / 写「已逾期」却还没到期）
- 日期倒挂检测（有效期至早于上次检验日期 / 上次检验日期晚于基准日）
- 检验周期非正检测（周期填 0 或负数）
- 重复证照编号检测
- 空白、占位符、无法识别的日期或数值检测

每条结论都带**台账原文行号**（形如「台账第 2 行「曳引驱动乘客电梯（1号梯）」（证照编号 梯110044010020240001）」），
可由第三方用同一份输入和同一口径复算；材料不足时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么

检查项以引擎导出的 CHECKS_GIVEN 为准，跑一次 `--sample` 就能看到实际执行了哪些。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看样例
node scripts/run.mjs --input 你的台账.json     # 跑自己的材料（{"text": "含表头的台账文本"}）
```

台账最少要有这些列：检查基准日、证照/设备名称、证照编号、类别、上次检验日期、检验周期（月）、
有效期至、距到期天数、状态。其余列（年检费用、预算费用、责任部门）有就一起核，
没有不影响前面 9 列的复算。从 Excel 复制成文本、Tab 分隔最稳。

日期可写 `2026-06-01` / `2026/6/1` / `20260601` / `2026年6月1日` 四种之一；
**台账里要留一列「检查基准日」**（就是这次核对的日子），距到期天数才有一个确定的口径 ——
本工具绝不按"打开表格的那天"去算，否则同一份台账每天结论都不一样。

## 常见错法（这张台账里真的会有人这么填）

1. **把「检查基准日」写成打开表格的那天**：同一份台账今天算 172 天、明天算 171 天，月度检查记录前后对不上。
   基准日应当是台账自己写明的那次核对日（本工具取表内最新日期，绝不取系统当天）。
2. **检验周期写成文字**：周期列是**月数**，电梯与压力容器填 12、危化品经营许可证填 36、排污许可证填 60；
   写成"一年""12个月"这类描述，这一行就无法参与复算。
3. **上次检验日期与有效期至填反**：有效期至早于上次检验日期就是日期倒挂（复算会直接报出来）；
   倒挂的日期算出来的到期风险一定是错的。
4. **状态列长期不更新**：设备已经过了有效期，台账上仍写着"有效" —— 月度检查的第一眼就被骗过去了。
   本工具按到期日与状态词判一致性，过期了还写"有效"会当场报出来。
5. **同一台设备换部门就新开一行**：两行都填同一个设备编号，重复送检、重复付费，到期项还会被数两遍。
6. **到期日填的是「送检日 + 周期」**：检验报告上的**检验日期**才是起点，把送检日当检验日，
   整条到期日会早算几天到几周；三处（检验报告、使用登记证、台账）对不上时以检验报告为准。
