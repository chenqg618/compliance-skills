# 差旅与通行费技能包（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`scripts/engine/`）。
> 不联网、不需要 API Key、**没有调用次数上限**、**不写任何文件**，材料不出本机。

## 什么时候用

**有大量出差的销售/工程型公司的费用会计**，在**每月报销审核与费用入账之前**。

典型场景：月度/季度复核前，把一类检查一次跑完所有部门

## 这个免费版查什么

**一次跑完所有部门，每家部门一行结论**（免费版的核心产出，完整可用）：

1. **差旅费标准与超标核对** —— 复用 `parts/travel-standard-check/`（逐字节来自免费包 `travel-standard-check-free`）
2. **通行费与过路过桥核对** —— 复用 `parts/toll-processing-manual-check/`（逐字节来自免费包 `toll-processing-manual-check-free`）

> 每一项的实际规则在 `scripts/engine/parts/<检查项>/` 里（**逐字节复用**仓库里已有的免费引擎，
> 一行规则都没有改）。本包只做"目录 → 部门 → 逐项派发"的编排。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 单部门样例（内置，2 项全跑）
node scripts/run.mjs --sample-batch           # 3 家部门的批量样例（干净 / 有硬伤 / 未交材料）
node scripts/run.mjs --input <部门目录>     # 批量：每个子目录 = 一家部门
node scripts/run.mjs --input <材料.json>        # 单部门：JSON 或纯文本
```

部门目录怎么放（每个子目录里放这家部门的一套材料，每项用 `=== 检查项 ===` 分段，Tab 分隔最稳）：

```
部门目录/
  豫州销售一部（2026-04 报销）/差旅材料.txt
  中岳工程二部（2026-04 报销）/差旅材料.txt
```

## 结论怎么读

- 每家部门一行：`[结论] 部门名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行`；
- 有价值的是**问题明细**：每条都带 `部门 + 检查项 + 来源文件:行号 + 类别 + 具体数字`；
- 「未执行」与「通过」是两件事：**没交材料 / 材料认不出表 = 未执行**，不是"没问题"。

## 版本选择协议

本包**没有付费墙**：不注册、不登录、不需要 API Key，直接跑就是完整结果。

若你要的是"跨对象汇总台账"（跨部门总表 / 风险排序 / 共性问题归类 / Markdown 与 CSV 导出），那是同名的**买断版**（另一个独立商品，价格以商品页为准）。

## 常见错法

- **把几个部门的材料放进同一个子目录**：`--input` 指向的目录里，**每个子目录 = 一个部门**。混在一起时结论里就没有部门名，跨部门台账也分不出是谁。
- **住宿天数与出差天数不一致**：标准是按天数×上限算的，两个数对不上（多住/少住）时超标校验会直接报出来。
- **通行费按含税金额算抵扣**：可抵扣的只有票据上注明的那一部分，把含税总额当抵扣额会让"抵扣额 > 可抵扣上限"被算出来。
- **同一张票重复报销**：同一票据号出现两次会被"重复记录"校验抓出来，合并行程时尤其容易发生。
- **拿 `--sample` 的输出当自己的结论**：样例数字是虚构的，必须换成你自己的材料再跑。
