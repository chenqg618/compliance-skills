# 口播脚本体检官（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`scripts/engine/` 目录）。
> 不联网、不需要 API Key、没有调用次数上限。**逐字稿不会离开你的机器。**

## 它体检什么

拿到一份口播逐字稿（带时间戳更好），输出五件事：

| 维度 | 具体输出 |
|---|---|
| 结构地图 | 钩子 / 痛点共鸣 / 论证干货 / 转折升华 / CTA 五段，哪段有、哪段缺、各占几句 |
| 开场钩子 | 九类钩子里命中了哪几类、强度几级、前 3 秒是否被客套话占掉 |
| 留存节奏 | 平均句长、长短句交替率、拖沓段位置、信息密度（字/秒） |
| 口语度 | 0-100 分；命中哪些书面语连接词、是否被动句、有没有人称与语气词 |
| CTA | 强度三级、出现在第几句、是否落在结尾 |

问题清单按 P0 / P1 / P2 分级，**每条都对应一条可复核的规则**，不是主观打分。

## 怎么用

```bash
node scripts/run.mjs --sample
node scripts/run.mjs --input my-script.json
node scripts/run.mjs --input my-script.json --json
```

入参就是一份 JSON，样例见 `templates/sample.json`：

```json
{
  "text": "00:03 大家好，今天我想跟大家分享一下……",
  "platform": "shipinhao",
  "goal": "follow",
  "duration": 68
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `text` | 是 | 口播逐字稿。可带 `00:03 ` 形式的时间戳，也可只给纯文本 |
| `platform` | 否 | `douyin` / `xiaohongshu` / `shipinhao` / `bilibili` / `kuaishou`，影响信息密度基准 |
| `goal` | 否 | `sale`（带货）/ `follow`（涨粉）/ `traffic`（引流）/ `brand`（品牌） |
| `duration` | 否 | 成片时长（秒），用于校准信息密度 |

## 触发条件

用户说以下任意一类话时使用：

- 帮我看看这条口播稿怎么样 / 这条脚本能爆吗
- 我的视频完播率低，是不是开场有问题
- 帮我拆一下这条短视频的脚本结构
- 这段口播太书面了 / 念起来不顺 / 不像人话
- 帮我体检一下这个逐字稿 / 给脚本打个分

## 常见错法（写口播稿的人真的会这么干）

1. **开头先自我介绍/问候**：前 3 秒被送掉，钩子强度判 0；把结论或冲突提到第一句。
2. **拿片段来测**：句子太少会直接判"材料不足" —— 留存节奏必须看完整稿。
3. **以为它会替你改稿**：它只给**结构诊断**（缺哪段、钩子强弱、CTA 强度、口语度），不润色、不代写。
4. **忽略"口语度"**：书面词太多（"综上所述""基于此"）会让完播率掉，分数低就该念出来顺一遍。
5. **没有时间戳却按实测读**：无时间戳时时长与语速是**估算**，只能看趋势不能当数据。

## 边界（先看这里，别误用）

**本技能只做机械层面的可复核判定**：结构是否齐全、开场是否被客套话占掉、句子是否过长、书面语连接词是否过多、CTA 是否落在结尾。

**它不判断、也无法判断**：

- 选题能不能爆 —— 那取决于赛道、账号权重、发布时间、平台流量池
- 内容是否真实、是否合规、是否有法律风险
- 画面、剪辑、BGM、字幕的配合
- 带货转化的真实结果

如果输入**不是口播稿**（例如产品说明书、论文、聊天记录、日记流水），**不要直接出结论**：先明确告诉用户「这段材料看起来不是口播逐字稿，体检结果会没有意义」，确认后再决定是否继续。

字数或句数不足时，脚本会以退出码 3 结束并说明缺多少，**不会编造一份看起来正常的报告**。
