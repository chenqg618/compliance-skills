# 课时消耗与教师课时费核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：教培机构的教务 / 财务 / 校区主管，在**每月算教师课时费**这条流程上：
先把学员课时包的「课耗」导出来，再按排课记录算老师该拿多少课时费，两张数必须对到一起才能发钱。
月底一次要核好几张表（多个教师、多个校区），核完就得往下走。

**这张表会逐项核对什么**（全是纯算术，几十上百行没人愿意手核）：

- **课时费 = 课时数 × 课时单价**：逐行复算，单价录错一位、课时数漏乘都是钱
- **正课 / 试听 / 补课的口径不一样**：试听与补课**不消耗学员课时**（补课是服务补救，原课次已经扣过），
  正课必须有课耗 —— 把两种口径混着填，学员课时包和教师课时费两边都对不平
- **学员消课课时 = 系统课耗课时**：两条线的数必须逐笔相等，差一笔就有一边算错了
- **合计行逐列复核**：课时消耗合计、课时费合计、代课补贴合计必须等于明细之和
- **课时单价 ≥ 合同保底单价**：低于保底的排课直接亏
- **重复课时记录与关键字段空缺**：同一教师同一天同一课型同样课时数的重复行、缺格与占位符

每条结论都带**原文行号与出处**（`文件名:行号`），可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看样例
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料
```

入参就是这张表本身：把**表头和数据行一起**复制成文本贴进来（从 Excel 复制，Tab 分隔最稳），
写成 `{"text": "…"}` 或直接粘纯文本都行；也可以用 `file` 字段给个材料名，结论里的行号会带上它。
表头必须能认出这 11 列：教师、校区、课程类型、上课日期、课时数、课时单价、课时费、
代课补贴、学员消课课时、系统课耗课时、合同保底单价（少一列就会直接说"材料不足"，不会猜）。

## 出参

`run(payload)` 返回 `{status, result}`：

- `status`：`success`（已执行检查）或 `insufficient_input`（材料不足，**此时没有 `result`，也不给任何结论**）
- `result.findings[]`：每条 = `level`（P0/P1）、`category`、`line`（**原文行号**）、`amount`、
  `message`（带具体数字）、`evidence`（`文件名:行号`）、`advice`（怎么改）
- `result.summary`：条数、P0/P1 计数、`hours_total` / `pay_total` / `subsidy_total` /
  `consumed_total` / `sys_consumed_total`、`verdict`（`NO_ISSUE_FOUND` / `NEEDS_REVIEW` / `ERROR_FOUND`）
- `result.checks_executed` / `checks_withheld`：本次**真的执行了**哪些、哪些**没有执行**（如实列出，不伪造）

## 常见错法（本产品专属）

1. **拿「上课课时数」当学员课耗**：老师上了 2 课时，可学员请假后没扣课时 —— 两边用的根本不是同一个数。
2. **试听 / 补课也扣学员课时**：试听不该扣；补课是服务补救，原课次已经扣过，再扣就是重复扣费。
3. **课时费与「课时数 × 单价」对不上**：常见是调价后只改了单价没重算课时费，或者课时费那一格直接手填。
4. **只贴数值区不贴表头**：表头缺了或认不出来，本工具直接说材料不足，而不是猜哪一列是什么。
5. **合计行漏改**：明细里加了一行，合计行没跟着更新，表面看一切正常，课时消耗合计却对不上。
6. **同一节课录两遍**：同一教师同一天同一课型同样课时数出现两行，课时费会翻倍；本表没有学员列，
   要区分不同学员请自己加一列学员或课次编号。
7. **课时单价低于合同保底价**：低价排课（体验价、内部价）必须先有特批依据，否则就是在亏。
