# 递延所得税与暂时性差异核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 不联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：财务、税务与审计岗在**每季度与年度汇算**时都必须核一遍递延所得税台账。
这张表把会计口径与税法口径的差额落在纸面上，四条链路串起来：

· 暂时性差异 = 账面价值 − 计税基础（**正数＝应纳税暂时性差异，负数＝可抵扣暂时性差异**）
· 递延所得税资产/负债余额 = 暂时性差异 × 适用税率（方向决定科目）
· 本期变动 = 期末余额 − 期初余额（再与利润表所得税费用勾稽）
· 可抵扣亏损：结转期用尽或确认条件不满足时**不得**确认递延所得税资产

税率用错、差异方向搞反、亏损条件不够却确认了资产 —— 是审计调整与税企争议的高发点。
纯算术加口径一致性，但行一多、税率多档、方向一转，人眼极易错。

**与已有能力的区别**：`cit-adjustment-check` 核的是**纳税调整明细**（调增调减、应纳税所得额）；
本技能核的是**递延所得税台账**（账面价值/计税基础 → 暂时性差异 → 递延余额与本期变动），
是资产负债表口径的另一张表。

## 这个免费版查什么

· 暂时性差异逐项复算（账面价值 − 计税基础）
· 递延所得税资产/负债余额复算（暂时性差异 × 适用税率）
· 本期变动勾稽（期末余额 − 期初余额）
· 方向标记与差异正负号的一致性核对
· 合计行逐列复核（每一列的合计是否等于各行之和）
· 重复项目检测
· 空白与占位符检测

（检查项由引擎的 `CHECKS_*` 导出，跑 `--sample` 会打印实际执行了哪些。）

```bash

```

入参就是一张**含表头**的台账，从 Excel 复制成文本粘进来最稳（Tab 分隔）：

```text
项目	方向	账面价值	计税基础	暂时性差异	适用税率	期初余额	期末余额	本期变动
固定资产（折旧年限差）递延所得税负债	应纳税	500000.00	400000.00	100000.00	5%	7500.00	5000.00	-2500.00
```

可抵扣亏损行再加两列：`未弥补亏损`、`亏损可结转期末`（写成 2027 或 2027-12）；
利润表行在「项目」列里写「所得税费用」即可，它的「本期变动」会与各项目变动合计比对。

## 常见错法（这张表里真的会有人这么填）

1. **把方向当符号用**：差异写成 −40000 却标「应纳税」，或写成 +40000 却标「可抵扣」。
   方向由 账面价值 − 计税基础 的正负决定：账面低于计税基础才是可抵扣。
2. **税率用错档**：同一主体 25% 的表里混进 15%、5% 的行，余额与本期变动会一起错；
   同一纳税主体的递延所得税原则上适用同一档税率。
3. **可抵扣亏损照抄上年**：结转期已过或没有「未来能取得足够应纳税所得额」的条件，
   仍确认递延所得税资产；确认额还应以 未弥补亏损 × 税率 为上限。
4. **本期变动不往回勾**：期末减期初算一遍就交，不与利润表「递延所得税费用」对（差额就是漏项或重复项）。
5. **合计行不跟着更新**：明细行改了、合计行还是旧数；或者同一项目按两档税率分行列示后没做区分。
6. **零差异行仍留方向标记**：差异为 0 却写着方向，下游按方向汇总时会多算一笔。
7. **缺格用 0 顶**：税率、计税基础空着就按 0 算 —— 本工具不会替你填，会直接报「关键字段缺失」。
