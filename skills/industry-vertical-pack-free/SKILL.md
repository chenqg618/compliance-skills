# 行业专项技能包（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`scripts/engine/`）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**、**不写任何文件**。

## 什么时候用

**谁会在什么时候用**：医院/诊所、学校/教培、餐饮、酒店、物流/出口、物业/公用事业、银行融资
这些行业机构的财务与业务岗，在**月度结账 / 日结 / 结算核对 / 申报之前**。
行业底稿从来不是一张表：门诊收费与退费日结、医疗收费与医保结算、医保拒付与申诉、
医保结算清单与 DRG 入组、医院耗材加成与零差率、药品耗材进销存与科室领用、教培课消与预收学费、
学费与退费、餐饮菜品成本与出品率、酒店夜审与房费收入、车辆保险与保费摊销、
银行贷款利息与还款计划、出口报关与收汇核销、电费分时计价 —— 每一项都有自己的勾稽关系，
逐张手核既慢又容易漏，而且月月重复。
一个集团往往同时管着**好几家机构**（几家医院 / 几个校区 / 几家门店 / 几条线路），
真正要做的事是"**一次跑完所有机构，每家机构一行结论**"。

**这个包做的事只有一件**：`--input <机构目录>`（每个子目录 = 一家机构 / 一套材料），
一次跑完所有机构，**每家机构一行结论**。

## 这个免费版查什么

下面 14 项，**每家机构都跑一遍**（检查项名字与引擎 `CHECKS_GIVEN` 逐条一致）：

1. 门诊收费与退费日结核对
2. 医疗收费与医保结算核对
3. 医保拒付与申诉核对
4. 医保结算清单与DRG入组核对
5. 医院耗材加成与零差率核对
6. 药品耗材进销存与科室领用核对
7. 教培课消与预收学费核对
8. 学费与退费核对
9. 餐饮菜品成本与出品率核对
10. 酒店夜审与房费收入核对
11. 车辆保险与保费摊销核对
12. 银行贷款利息与还款计划核对
13. 出口报关与收汇核销核对
14. 电费分时计价核对

引擎里的 `CHECKS_WITHHELD`（本免费版**不执行**的项）会逐条打印出来，例如
「跨机构汇总台账」「行业风险排序清单」「跨机构共性问题归类」「行业台账导出」——
**它们是"未执行的检查项"的说明文本，不是实现**。

另外，每个成员检查包**自己**没做的子检查（`SUB_CHECKS_WITHHELD`，本包合计 69 项）也在结果里
`scope.sub_checks_not_run` 如实列出 —— 两个档位都没实现它们，不会因为「买了完整档」就让买家以为这些项被跑了。

## 怎么用

```bash
node scripts/run.mjs --sample                  # 单机构样例（内置）
node scripts/run.mjs --sample-batch            # 3 家机构的批量样例（干净 / 有硬伤 / 没交材料）
node scripts/run.mjs --input 机构目录            # 批量：每个子目录 = 一家机构
node scripts/run.mjs --input 机构目录 --json     # 机器可读
```

机构目录怎么放（每个子目录里放这家机构的一套材料，每项用 `=== 检查项 ===` 分段，Tab 分隔最稳）：

```
机构目录/
  豫州第一人民医院/机构材料.txt
  中岳教育集团/机构材料.txt
```

也可以把 14 张表拆成 14 个文件放进同一个子目录 —— 引擎会自己认表头找对应的那一项。
`templates/sample.json` 是引擎自己的样例，可以直接 `--input` 它先跑通一遍。

**退出码**：0 已执行检查 / 1 缺少入参 / 3 材料不足 / 4 入参读不到或无法解析 / 9 未预期错误。
**材料不足**（一家机构的材料都没有、材料为空或只有几行、认不出任何一张表）时，
本工具**不做任何认定、也不给任何结论**，打印缺什么并以退出码 3 结束 —— 不会把"没查"说成"通过"。

## 结论怎么读

- 每家机构一行：`[结论] 机构名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行`；
- 有价值的是**问题明细**：每条都带 `机构 + 检查项 + 来源文件:行号 + 类别 + 具体数字`，
  第三方可以拿同一份材料复算；
- 「未执行」与「通过」是两件事：**没交材料 / 材料认不出表 = 未执行**，
  不会被算成"没问题"（材料只覆盖一部分时还会单独报一条覆盖缺口）。

## 常见错法

- **把所有机构的材料放进同一个子目录**：`--input` 指向的目录里，**每个子目录 = 一家机构**。
  把三家医院的材料倒进一个机构目录，会被当成**一家**机构，集团层面的机构 × 检查项对照也就无从谈起。
- **把 14 项的材料全塞进一个文件却不分段**：引擎按 `=== 检查项 ===` 分段找每一项的表；
  不分段时只有第一段能被认出，其余 13 项会如实标成「未执行」并报一条「材料只覆盖了一部分」，
  不是"查过了没问题"。
- **以为「未执行」=「通过」**：某家机构只交了 3 张表，那 3 项之外的 11 项是**没有核**，
  结论里写的是「未执行」，并且会单独报一条覆盖缺口。
- **同一个机构目录里混着两家机构的表**：引擎会按表头把能认出的段跑完，
  于是"甲医院的医保结算表"可能被当成"乙医院的"，行号对得上但主体是错的 ——
  **一家机构一个目录**是唯一稳的放法。
- **拿 `--sample` 的输出当自己的结论**：样例只是让你确认「跑得通、格式对」，
  真正的结论必须来自你自己的材料。

## 使用次数与完整档

本免费版每次运行结束后会向服务端做**一次匿名次数统计**：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），**不发送你的材料、不写任何文件**。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 统计不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 跨机构汇总台账（全部机构 × 全部 14 项检查合并成一张总表）
- 行业风险排序清单（按 P0/P1/P2 排序，带机构名与原文文件行号）
- 跨机构共性问题归类（同一个问题命中 2 家及以上机构时合并成一条共性项）
- 行业台账导出（Markdown 与 CSV 文本，直接用于集团月度复核说明）

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 边界（请务必知道）

- **不做**行业定价判断：收费项目、医疗服务价格、学费标准、房价、运价、电价该怎么定，
  属于定价与行业政策判断，本工具不回答；
- **不判断**医保该不该付、DRG 该怎么入组、拒付申诉能不能成功；**不判断**各行业的地方性政策口径是否最新；
- **不代替审计**，也不出具鉴证意见或审计意见；**不核对**医保结算回执、银行回单、报关单、缴费凭证的真伪；
- **不读取**收费系统 / 教务系统 / POS / PMS / 报关系统的导出文件 —— 需要你先导出成文本，每家机构一个目录。
