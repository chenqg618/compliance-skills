# SaaS订阅用量与超额计费核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：SaaS 公司的**出账岗 / 商务 / 财务**，以及企业客户（甲方）的**财务**，
在**每月出账、客户对账、续费谈判**这几个固定节点上，都得把这张订阅用量与超额计费明细表核一遍才能往下走。
超额费多算、账单对不上、重复开通，正是双方每月都要吵的几件事。

**这张表会逐项核对什么**：

- 超额用量 = max(0, 实际用量 − 套餐额度)
- 超额费用 = 超额用量 × 超额单价
- 账单金额 = 套餐费 + 超额费 + 坐席费 − 折扣
- 套餐额度是否远高于实际用量（套餐买大了、白付套餐费）
- 同一账期不得出现同一订阅号两行；关键格不得留空或写占位符

每条结论都带**原文行号与订阅号**，可被第三方用同一口径复算；
材料不齐时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么

1. 超额用量复算（超额用量 = max(0, 实际用量 − 套餐额度)）
2. 超额费用复算（超额费用 = 超额用量 × 超额单价，逐行复算）
3. 账单金额勾稽（账单金额 = 套餐费 + 超额费 + 坐席费 − 折扣）
4. 用量与套餐额度适配检测（实际用量远低于额度 ⇒ 套餐买大了、白付套餐费）
5. 同一账期同一订阅号重复行检测
6. 关键字段缺失或为占位符检测

（检查项由引擎的 `CHECKS_GIVEN` 导出，跑 `--sample` 会打印实际执行了哪些；
本版本不包含的 5 项列在 `CHECKS_WITHHELD` 里，不做也不假装做。）

**数字会做归一化**：`12,000`（千分位）、`1240元`、`(120)`（会计负数）、`0.5%`（折成 `0.005`）
都会被认成同一个口径；超额单价列写 `0.5` 表示每个用量 0.5 元，本工具不会替你猜你的意思。
表头里的空格、全角括号与单位后缀会被忽略，所以「实际用量(次)」和「实际用量」都认；
表头是**完全相等**匹配的，所以「套餐额度」不会把「套餐费」抢走、「超额用量」不会把「超额单价」抢走。

## 常见错法（本产品专属）

1. **把年付套餐的整年额度砸在一个月里**：套餐额度要按账期摊（年付 ÷ 12）。
   额度填成整年的数，超额用量会被算成 0（漏收）；一行填年度额度、另一行填月度额度，
   同一客户同一账期的超额就直接矛盾。本工具只核 `max(0, 实际用量 − 套餐额度)` 这个算术，
   **额度怎么摊是你的合同口径**，所以它把不符的行连同行号列出来让你核口径，而不是替你改。
2. **超额单价取错档 / 调价前后混用**：调价生效日前后混在一张表里，同一客户相邻两行出现两个单价。
   超额费用 = 超额用量 × 超额单价，单价错一档，金额直接差一个比例。
   按「千次」计价却按实际用量乘，也会差出数量级 —— 请按合同的计价条款逐行复算。
3. **折扣减了两次、或者账单金额没跟着明细刷新**：账单金额 = 套餐费 + 超额费 + 坐席费 − 折扣，
   这一格是**要付出去的钱**（公司据此确认收入）。明细改过之后账单没重算，是出账期最常见的错。
4. **实际用量没超额度，超额用量却填了数**：多半是把上月的超额量带过来了，
   或者把两个订阅的用量加总后拿去比一个订阅的额度。本工具会把这一行单独点出来并说明"本应是 0"。
5. **该填 0 的格子留空**：没有超额的订阅，超额用量 / 超额单价 / 超额费用留空，
   会让这一行整行复算不出来。留空就是"不知道"，本工具宁可报缺格，也不用 0 替你假设。
   `待确认`、`待核` 这类占位符和留空一样对待。
