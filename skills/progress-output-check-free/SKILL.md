# 工程进度款与产值确认核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：施工/工程类企业的预算员、财务在**每月报进度款**这条流程上：
项目部先报「本期申请产值」→ 监理/业主做「产值确认」核成「本期确认产值」→ 才按合同支付比例算钱。
这一步必须把表核一遍才能往下走。

**这张表会逐项核对什么**（全是纯算术，几十个标段人眼核不动）：

- 本期**确认**产值 与 本期申请产值 是否一致（核减/核增必须在表里有依据）
- 本期应付进度款 = 本期**确认**产值 × 支付比例（基数用错了就是几万块）
- 累计确认产值 = 上期累计确认产值 + 本期确认产值（滚动栏最常忘了改）
- 本期实付 = 本期应付进度款 − 本期扣质保金
- 合计行逐列复核；重复标段/合同行与关键字段空缺检测

每条结论都带**原文行号与出处**（`文件名:行号`），可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 常见错法（这张表里真的会有人这么填）

1. **拿申请产值当基数**：本期申请 80 万、确认核成 76 万，进度款却按 80 万乘比例 —— 多付的那部分要追回来。
2. **累计栏不滚动**：本期确认值改了，「累计确认产值」还停在上个月的数；累计错会一路污染后续月份的超合同判断。
3. **用「本期实付」抹平差额**：扣质保金、代扣税、水电费、罚款要各占一列写清楚，不要只在实付栏填一个"差后数"。
4. **合计行漏改**：明细里加了一个标段，合计行没跟着更新，表看上去一切正常。
5. **只贴数值区**：没有表头（或表头被合并单元格拆散）时认不出列，本工具会直接说材料不足，而不是猜。
6. **比例与金额混用单位**：支付比例写成 `0.8` 或 `800%`，会让应付直接差一百倍。


## 使用次数与完整档

本免费版每次运行结束后会向服务端做**一次匿名次数统计**：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），**不发送你的材料、不写任何文件**。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 统计不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**；
· 不想要这次统计可以加 `--no-stats`（核对功能完全不受影响，只是拿不到完整档说明）。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。
