# 门店毛利与损耗核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**、材料不出本机。

## 什么时候用

**谁在什么时候用**：门店财务 / 会计 / 店长在**每月结账、月度经营分析、盘点差异复核**这类固定节点上，
必须先把「门店销售与成本毛利表」核一遍才能出毛利表、才能拿它做门店对比与考核。
这张表算错的方向只有两个 —— **毛利被算多了**（成本填少、损耗没进成本、收款没走账）
或 **毛利被算少了**（销售额漏记、重复扣成本、损耗重复计）；两条都会在月报和审计抽样上暴露，
而且**结完账就看不出来了**。

**这张表会逐项核对什么**（免费版执行 5 类，逐条都带**原文行号**）：

1. **销售额与收款勾稽** —— 收款合计 − 销售额 = 差异；收款大于销售额、或差异超过销售额的 0.5% 都提示
   （一个数从 POS 出、一个数从收银 / 银行流水出，两边对不上说明至少有一边不完整）。
2. **成本与理论成本差异复算** —— 实际成本 − 理论成本 = 成本差异，差 1 分钱也会报。
3. **毛利率逐行复算** —— 毛利 ÷ 销售额 = 毛利率，同时核 毛利额 = 销售额 − 实际成本。
4. **损耗率超限** —— 损耗金额 ÷ 损耗前库存金额 > 2% 提示；并核这一列的比率与两个金额是否自洽。
5. **重复行与关键字段空缺检测** —— 同一门店同一品类同一期间的整行重复、必需列为空或「待填」占位符。

每条结论都带**原文行号与出处**，可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么，也不会用默认值编出结论。

## 查什么 / 不查什么

**查**：只查**表内勾稽**（上面 5 类）—— 即"这一格能不能由同一张表的其他格算出来"。

**不查**（本版本不执行的检查项会如实列在输出的 `checks_not_run` 里，绝不会伪造）：

- 毛利额变动的三因素归因（销量 / 售价 / 单位成本）；
- 按毛利额排序的门店 × 品类整改清单与跨门店损益台账。

## 出参

- `status`：`success` 才有结论；`insufficient_input` 表示材料不足，此时**没有** `result`、**没有** `findings`。
- `result.findings[]`：每条含 `level`（P0/P1）、`category`、`line`（**原文行号**）、`message`（含算式与差异金额）。
- `result.summary`：`rows / periods / total / p0 / p1 / verdict`（`NO_ISSUE_FOUND` | `NEEDS_REVIEW` | `ERROR_FOUND`）。
- `result.scope`：本次执行的 `checks`、未执行的 `checks_not_run`、`executed_locally: true`、`network_used: false`。
- `result.checks_out_of_scope`：本工具**根本不做**的判断清单（边界诚实）。
- CLI 退出码：`0` 已执行检查 / `1` 没给入参 / `3` 材料不足 / `4` 入参读不到或无法解析 / `9` 未预期错误。

## 常见错法（本产品专属）

1. **销售额与收款的口径没对齐**：销售额取 POS 的**含税含折扣后**金额，收款却是银行到账额
   （已扣平台手续费、T+1 未到账）—— 差异会长期固定在一个百分比上。要么两边都取含税未扣费口径，
   要么把手续费与在途单列；不能一边含费一边扣费。
2. **损耗率的分母用了期末库存**：分母必须是**损耗前**库存金额。用期末库存（已扣损耗）当分母，
   损耗率会被系统性算高，全表看着都超标。分母口径写清楚再填。
3. **损耗金额同时进了成本和单独一列**：成本里已经含损耗、又在「损耗金额」列再列一次，
   毛利被扣两遍；或者成本不含损耗、损耗却没进损益 —— 毛利率与损耗率会同时"看起来正常"。
   先定：损耗进不进这条品类的成本，然后全表统一。
4. **毛利率的分母用毛利额**：毛利率 = 毛利 ÷ **销售额**，不是 ÷ 毛利额。Excel 下拉公式时引用错列，
   整列会一起失真（本工具逐行复算能抓出来，但口径本身要先定）。
5. **多期表直接相加当合计**：同一门店同一品类跨两个期间的两行是**正常的**（不算重复），
   但把两期的金额顺手加进同一行合计就会让合计与明细对不上。合计行只加本期明细。
