# 网点运费与代收货款结算核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：快递 / 快运网络里网点的**对账岗、财务**，以及总部的**结算岗**，
在**每月网点与总部结算（月结）时**把这张网点运费结算单与代收货款明细表核一遍才能划款。
运费少收、代收货款少缴、重复导单，正是网点与总部每月都要吵的几件事。

**这张表会逐项核对什么**：

- 运费 = 计费重量 × 计费单价
- 代收手续费 = 代收货款 × 代收手续费率；代收货款应缴 = 代收货款 − 代收手续费
- 应结金额 = 运费 + 派费 + 附加费 − 中转费 − 代收货款应缴
- 计费重量不得小于实际重量（否则就是少计费、运费少收）
- 同一网点同一期间不得出现同一运单号两行；关键格不得留空或写占位符

每条结论都带**原文行号与网点 / 运单号**，可被第三方用同一口径复算；
材料不齐时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么

1. 运费复算（计费重量 × 计费单价 = 运费）
2. 代收货款扣减复算（代收手续费 = 代收货款 × 代收手续费率；代收货款应缴 = 代收货款 − 代收手续费）
3. 应结金额复算（运费 + 派费 + 附加费 − 中转费 − 代收货款应缴 = 应结金额）
4. 计费重量低于实际重量检测（少计费、运费少收）
5. 同一网点同一期间同一运单号重复行检测
6. 关键字段缺失或为占位符检测

（检查项由引擎的 `CHECKS_GIVEN` 导出，跑 `--sample` 会打印实际执行了哪些；
本版本不包含的 5 项列在 `CHECKS_WITHHELD` 里，不做也不假装做。）

**数字会做归一化**：`1,240.00`、千分位、带货币符号的写法、`(1240)`（会计负数）、`1%` 都被认成同一个口径
（`1%` 折成 `0.01`；费率列写 `0.01` 或 `1%` 都行，写 `1` 表示 100%，本工具不会替你猜）。
表头里的空格与括号会被忽略，所以「计费重量(kg)」和「计费重量」都认。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看样例
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料
node scripts/run.mjs --input 你的材料.json --json
```

入参就是**含表头**的一张表（`{"text": "结算期间\t网点编码\t运单号\t…"}`）：
从 Excel 或快递系统结算导出里直接复制成文本（Tab 分隔最稳）贴进去即可。
表头缺列会明确告诉你缺了哪一列；**缺一列就不给结论**，不会拿 0 替你假设"这笔没有代收货款"。

非代收货款运单请把「代收货款 / 代收手续费率 / 代收手续费 / 代收货款应缴」都填 `0`：
填 `0` 表示"确实没有"，留空表示"不知道"，这两者不能混。

## 常见错法（这张表里真的会有人这么填）

1. **计费重量比实际重量还小**：计费重量是"实际重量与体积重取大、再按进位规则进位"的结果，
   正常只可能 ≥ 实际重量。抄了实重、漏了体积重、续重进位没做，都会让运费整体少收；
   本工具按 计费重量 × 单价 折算少收金额，并把这一行点出来。
2. **代收货款应缴没扣手续费、或手续费扣了两遍**：代收货款是替寄件人收的钱，
   只有代收手续费能留下。常见错法是"手续费算对了却没从应缴里减"，或者"减了一次又减第二次"，
   这一行内部就对不上（`代收货款 − 代收手续费 ≠ 代收货款应缴`）。
3. **费率写成 1 而不是 1%**：费率列写 `0.01` 或 `1%` 都认；写成 `1` 意思是 100%，
   手续费会被算成"整笔代收货款"，应结金额当场差出好几百。本工具不会替你猜你的意思。
4. **同一张运单导了两次**：重复粘贴 / 重复导单时，同一网点同一期间会出现两行同一运单号，
   运费与代收货款应缴一起算了两遍。本工具报重复行；确属同一票货分两段计费的，请拆成两行并写清说明。
5. **该填 0 的格子留空**：非代收货款运单的代收货款 / 费率 / 手续费 / 应缴留空，
   会让这一行整行复算不出来。留空就是"不知道"，本工具宁可报缺格，也不用 0 替你假设。
