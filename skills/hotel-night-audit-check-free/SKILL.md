# 酒店夜审与房费收入核对（免费）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 不联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：财务、出纳等岗位在**每月结账 / 对账 / 盘点**这类固定节点上，
必须把这张表核一遍才能往下走。

**这张表会逐项核对什么**：酒店夜审与房费收入表的逐行算术、合计勾稽、重复与空缺检测。

每条结论都带**原文行号与出处**，可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么

1. **应收房费复算**：出租间夜 × 平均房价 = 应收房费
2. **实收合计复算**：前台现金 + 前台刷卡 + 渠道预付 + 挂账 = 实收合计
3. **合计行逐列复核**（平均房价这类均价列不参与加总）
4. **同一房号同一营业日期重复行检测**
5. **空白与占位符检测**
6. **金额或间夜为负检测**

完整档追加的检查项见 `CHECKS_WITHHELD`；跑 `--sample` 会打印本次实际执行了哪些。

## 常见错法（夜审表真的会填错的写法）

1. **把「平均房价」也加进合计行。** 平均房价是均价列，各行的均价相加没有意义 —— 加进去当然对不上各行之和，于是天天报「合计不符」，真正的长短款反而被淹掉。均价列必须排除在加总之外。
2. **把「可售间夜」和「出租间夜」当成同一列。** 两个表头都含「间夜」；别名表里只要宽泛的「间夜」排在前面，这一整列就会被它抢走 —— 不报缺列、不报错，只是从此静默算错。
3. **拿「实收合计」直接去对「应收房费」，跳过四路分项。** 必须先核「现金 + 刷卡 + 渠道预付 + 挂账 = 实收合计」，再谈实收与应收的差额；两步混成一步，差额出在哪一路就说不清了。
4. **换房 / 续住 / 凌晨房被重复计间夜，当成重录处理。** 同一房号同一营业日期出现两行，多半不是重录，而是换房各记了一笔；先判断该不该合并，再动收入与间夜。
5. **把当天的冲回、退款、免单直接写成负数冲减本班收入。** 负号留在收入列里会把四路分项与合计一起拉偏；冲回与免单应当单独列示，而不是混进本班收入 —— 引擎会把负数单独报出来。
