# 安全教育培训记录与签到核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：制造业 / 建筑业 / 物业 / 危化企业的**安环部（安全员、培训管理员）**，
在三个固定节点上必须把这张表核一遍才能往下走：

- **每月安全培训台账复核**：月底把当月所有培训记录对一遍，再报给分管领导与上级主管部门；
- **新员工入职建档**：新员工三级安全教育（厂级 / 车间级 / 班组级）记录要齐、要有签到与考核成绩；
- **上级检查 / 执法检查前自查**：把「应培训人员名单 - 培训计划 - 签到与学时 - 考核成绩」对成一套能查的档案。

**为什么必须核（真实痛点）**：《安全生产法》要求新员工做**三级安全教育**、转岗与复工人员重新培训、
特种作业人员持证上岗、每年**再教育学时**达标，而且签到表、试卷 / 考核成绩、培训内容记录都要能查到。
检查时最常见的处罚情形正是「**签到表上有名字、学时不够**」「**新员工没做三级教育就上岗**」
「**培训记录与出勤/工时对不上**」—— 这些不是态度问题，而是台账上跨列的数字对不上。
一张几十人的培训表，人工核要小半天，还容易漏人、漏层级、漏补考记录。

**这张表会逐项核对什么**：培训记录的逐行算术（起止时间 → 学时 → 计划学时）、
每人年度累计学时与规定下限、应培训名单与签到名单的差集、同一人同主题同日期的重复登记、
考核成绩与合格线（含补考记录）、以及空白 / 占位符 / 时间与日期格式 / 负学时。

每条结论都带**原文行号、原文数字与时间**，可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺哪几列。

## 这个免费版查什么（6 项）

1. **学时勾稽** —— 逐行复算 `结束时间 − 开始时间` 得实际学时，再与「学时」「计划学时」两列比对，不等于就报出差额。
2. **再教育学时达标** —— 每人的「年度累计学时」与「规定下限」比对，不达标**点名到人**（一人只报一次）。
3. **应培训人员覆盖** —— 「是否应培训」与「是否签到」对账：应培训却没签到、不在名单却签到了，逐行点名。
4. **重复登记检测** —— 同一人 + 同一培训主题 + 同一培训日期登记了两次以上，会指出第一次出现在第几行。
5. **考核成绩与合格线** —— 成绩低于合格线即报出（带分数差），补考成绩为空的一并指出「补考记录缺失」。
6. **空白 / 占位符 / 格式 / 负学时** —— 关键字段空白或「待填」、时间或日期格式不合法、
   学时等数值看不懂或为负，逐行点名，不会把看不懂的值当成 0。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看样例
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料
```

入参就是一张表：把 Excel 里的**表头 + 数据行**一起复制成文本，放进 `{"text": "…"}`（Tab 分隔最稳）。

必需列（缺任何一列只会告诉你「材料不足、缺哪几列」，**不会给结论**）：

姓名、部门/班组、岗位、培训类型、培训主题、培训日期、开始时间、结束时间、学时、计划学时、
是否签到、考核成绩、合格线、年度累计学时、规定下限。

可选列（填了就让对应核对更准）：是否应培训、补考成绩、教育层级、特种作业证号（按掩码写，如 320101********1234）、
证件到期日、岗位应训主题、出勤时间段、备注。

## 常见错法

1. **学时列直接抄「计划学时」，不按签到表的起止时间复算** —— 半天课写成 8 学时、迟到早退不扣，
   算术上一眼能看出来，检查时就是「签到有、学时不够」。
2. **年度累计学时按计划学时累加，或把未签到的班次也算进去** —— 再教育学时虚高，
   一比对签到表就露馅；累计学时必须是**实际完成并签到**的学时。
3. **新员工三级教育只做了厂级就上岗，车间级 / 班组级"回头补"** —— 补记时又不写「教育层级」，
   三个层级在台账上断档；本版本只核表内数字，层级记录是否齐全要么补齐层级列、要么人工核。
4. **考核不合格只写"不合格"，补考成绩空着或写成"及格""合格"这类文字** ——
   空着算**补考记录缺失**，"及格"这类文字会被报**数值无法解析**，补考分数要填分数本身。
5. **培训日期 / 时间写成"3月2日""上午8点半"这类文本** —— 同一天会被当成两天（重复登记查不出来），
   学时也算不出来；日期统一成 `2026-03-02`，时间统一成 `08:30`。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 三级教育层级完整性（新员工必须同时有 厂级 / 车间级 / 班组级 三条记录，缺哪一级点名到人）
- 特种作业证有效期覆盖（培训 / 作业日期 不得晚于 证件到期日）
- 培训内容与岗位风险匹配（按「岗位应训主题」清单逐项检查该人是否缺训）
- 培训记录与工资 / 考勤时间冲突（培训时间段 与 出勤时间段 重叠即报出）
- 分部门×分培训类型汇总清单（按未达标人数排序，给出可整改动作）+ 整改清单 consolidated_actions

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 使用次数与完整档

本免费版会在**本包目录**里记一个使用次数（`scripts/.hint-count`，一个整数，不含任何机器或用户信息）。

· 前 3 次：**完全离线**（不发生任何网络请求），输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 第 4 次起才会向服务端问一次（只发包标识与次数），拿回完整档说明；
· 请求不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**；
· 不想要这次统计可以加 `--no-stats`（核对功能完全不受影响，只是拿不到完整档说明）。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

## 边界（请务必知道）

本工具**不做**引擎 `CHECKS_OUT_OF_SCOPE` 里列的那些判断：不判定培训是否真实发生、
不判定培训内容在专业上是否充分、不代替《安全生产法》与地方规定给出合规结论、
不读 .xlsx / .pdf 原件、核对过程不联网核验证书真伪。

材料不足时**不给结论**，也不会输出「未发现问题」；本版本未执行的检查项会如实列在结果里。
