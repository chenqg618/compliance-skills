# 生产投入产出与报废率核对（免费）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：财务、出纳等岗位在**每月结账 / 对账 / 盘点**这类固定节点上，
必须把这张表核一遍才能往下走。

**这张表会逐项核对什么**：生产投入产出与报废表的逐行算术、合计勾稽、重复与空缺检测。

每条结论都带**原文行号与出处**，可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么

引擎逐条执行下面这 6 项（本版本不执行的检查项会如实列在结果的 `scope.checks_not_run` 里）：

1. **投入产出与报废量勾稽复算**：完工量 + 报废量 = 投入量 − 期末在制
2. **良率与完工量复算**：良率 = 完工量 ÷ 投入量
3. **合计行逐列复核**：投入量 / 完工量 / 报废量 / 期末在制 四列逐列与明细相加对
4. **同一工单同一工序重复行检测**（跨工序的多行是正常转序，不算重复）
5. **空白与占位符检测**（工单号 / 期间 / 工序 / 各数量与率）
6. **数量为负检测**（投入量 / 完工量 / 期末在制）

```bash
node scripts/run.mjs --sample                 # 先看样例

```

## 常见错法（这张表里真的会有人这么填）

1. **完工量填成"入库量"、期末在制漏填**：完工量要含已完工但还没入库的成品；只填入库量，
   「完工 + 报废 = 投入 − 在制」当场就闭环不了，看着像料丢了，其实是口径写窄了。
2. **良率是上个月手抄下来的**：月底改了完工量却忘了改良率（或改了良率没改完工量），
   表面良率虚高——免费版会把两个数拉出来复算，一算就露。
3. **报废量里塞"让步接收 / 降级使用"，或者把返工写成负报废**：让步接收、降级品不是报废，
   返工返修也不是负报废；混进来报废率不是虚高就是虚低，两个方向都会看错损失。
4. **合计行是手工拉的、插行后没重算**：新插一行明细忘了改合计（还有把"良率 / 报废率"两列也去求和的），
   整表就和明细对不上——率列不能相加，只能重新按总量算。
5. **同一工单同一工序贴了两遍**：两个班组各报一次、两张 Excel 合并时又没去重，
   数量被重复统计（注意：同一工单的**不同工序**多行是正常转序，不算重复）。


## 使用次数与完整档

本免费版每次运行结束后会向服务端做**一次匿名次数统计**：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），**不发送你的材料、不写任何文件**。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 统计不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 报废率超过参考上限（3%）提示（参考口径）
- 良率与报废率之和不为 1 检测（期末在制为 0 的行）
- 投入量为零却有报废检测
- 报废量为负（返工/退料误记）提示
- 工序间数量不匹配（上工序产出 ≠ 下工序投入）提示

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 边界（请务必知道）

本工具**不做**引擎 `CHECKS_OUT_OF_SCOPE` 里列的那些判断；
材料不足时**不给结论**，也不会输出「未发现问题」。
