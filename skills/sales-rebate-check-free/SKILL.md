# 销售返利与渠道返点核对（免费）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 不联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：**快消/建材/家电等有渠道返利的销售财务与商务**，在**月度计提返利、季度/年度兑付之前**：

- 应计返利 = 计算基数 × 返利比例；
- 期末已计提未兑付 = 期初已计提 + 本期计提 − 本期实际兑付；
- 本期实际兑付不得超过（期初 + 本期计提），否则就是超兑。

> 与已有产品的关系：`purchase-rebate-check`（采购返点）核的是**应向供应商收取**的返利；本产品核的是
> **应付给客户/渠道**的返利负债（先计提、后兑付）——两侧口径与勾稽关系不同。

## 这个免费版查什么

1. **合计行逐列复核**（计算基数/应计返利/期初已计提/本期计提/本期实际兑付/期末已计提未兑付）；
2. **应计返利 = 计算基数 × 返利比例**（容差 0.02，P0）；
3. **期末未兑付 = 期初已计提 + 本期计提 − 本期实际兑付**（P0）；
4. **本期实际兑付为负**（P0）；
5. **应计返利为负**（P1）；
6. **客户/渠道+返利政策重复行**检测；
7. **空白与占位符**检测（含必需列缺失，仍照常给结论）。

## 常见错法（这些表里真的会有人这么填）

1. **比例填 `3` 而不是 `3%`**：本工具两种写法都认（`3` 按 3 个百分点、`0.03` 按 3%），但**别把 `0.03` 当成 0.03 个百分点**——比例口径要在全表统一。
2. **基数用含税销售额**：返利基数通常按**不含税**销售额或政策约定的口径，用含税会让应计返利整体偏高。
3. **先兑付后计提**：本期兑付超过"期初 + 本期计提"就是超兑，会被完整档直接点出来——兑付前要先确认计提依据。
4. **渠道层级重复计算**：同一笔销售既给经销商返利又给门店返点（重复计入同一基数）会报重复行或比例失真。
5. **兑付方式留空**：兑付方式（银行转账/抵扣货款/平台账单抵扣）影响后续核销，留空无法复核。

## 边界（请务必知道）

- **不做**会计判断：返利该冲减收入还是计入销售费用、何时确认，请按准则与公司政策判断；
- **不代替**审计程序或出具鉴证意见，也不判断返利政策是否构成价格折让；
- **不核对**返利协议、结算单、银行回单的**真伪**，也不与渠道系统逐行比对；
- **不读取** CRM / 渠道系统 / 财务系统的导出文件——需要你先导出成文本贴进来；
- **不判断**返利的发票与税前扣除口径（属于税务判断）。
