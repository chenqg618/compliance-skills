# 跨境电商平台佣金与广告费核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：做跨境电商的财务、运营、店主，在**每月和平台对账**这个固定节点上，
必须把平台结算单和广告费账单核一遍，才能确认这个月到底该收多少钱。

**触发场景**：平台结算单与广告费账单对不上、佣金扣得比算出来的多、
结算净额和「销售额 − 佣金 − 广告费 − 其它费用」差一截、怀疑同一笔结算被算了两遍。

**这张表会逐项核对什么**：平台结算单与广告费账单的逐行算术、两张表之间的广告费勾稽、
合计行勾稽、重复结算与空缺列检测。

每条结论都带**原文行号与出处**，可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么

（检查项由引擎的 `CHECKS_*` 导出，跑 `--sample` 会打印实际执行了哪些。）

- 平台佣金逐行复算：佣金 = 销售额 × 佣金率
- 广告费勾稽：结算单列示的广告费 = 广告费账单金额
- 结算净额逐行复算：净额 = 销售额 − 佣金 − 广告费 − 其它费用
- 合计行逐列复核：每一列的合计 = 各明细行之和
- 重复结算检测：同一店铺 + 平台 + 站点 + 期间出现多行
- 关键字段缺失与占位符检测（缺失时不复算、不套默认值）

## 需要准备什么材料

一张**含表头**的平台结算单与广告费账单汇总（从平台后台导出后，连同表头一起复制成文本，Tab 分隔最稳）。
至少要能认出这几列：

| 列 | 说明 |
| --- | --- |
| `销售额` | 本期结算基数（也接受「结算基数 / 成交金额 / GMV」） |
| `佣金率` | 账单自己列示的费率，写 15 或 15% 都行 |
| `佣金` | 本期平台实际扣的佣金 |
| `广告费平台账单` | 广告费账单上这一行对应的金额 |
| `广告费` | 结算单上列示的广告费 |
| `其它费用` | 仓储 / 退款 / 支付手续费等扣项 |
| `结算净额` | 平台实际打款金额 |

`店铺 / 平台 / 站点 / 期间` 这几列有就用、没有也能跑（有的话结论里会点名是哪一行）。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看样例（干净样例，0 条发现）

```

入参写法（两种都行）：

```json
{"text": "店铺\t平台\t站点\t期间\t销售额\t佣金率\t佣金\t广告费平台账单\t广告费\t其它费用\t结算净额\n..."}
```

**退出码**：`0` 已执行检查 / `1` 没给入参 / `3` 材料不足（此时**不出结论**）/
`4` 入参文件读不到或无法解析 / `9` 未预期错误。

## 出参

`--json` 输出可直接被程序消费：

- `result.findings[]`：每条含 `level`（P0/P1/P2）、`category`、`line`（原文行号）、
  `message`（差额与复算过程）、`advice`（下一步怎么查）、`basis`（原文引用）
- `result.summary`：行数 / 店铺数 / 平台数 / 站点数 / 期间数、各级别条数、各列合计
- `result.scope.executed`：**本次实际执行的检查项**（免费档 6 条）
- `result.scope.checks_not_run`：**本版本未执行的检查项**（如实列出，绝不用默认值编造）
- `result.checks_out_of_scope`：本工具**根本不做**的判断

0 条发现时另给 `result.note`，写清"通过"到底意味着什么、以及不意味着什么。

## 本产品专属的常见错法

1. **把两张表的金额贴成一列**：结算单的「广告费」和广告费账单的金额必须各占一列。
   只贴一列时，广告费勾稽会退化成"自己减自己"，永远通过 —— 这是最隐蔽的假通过。
2. **佣金率写成金额**：写成 `18000` 而不是 `15`（或 `15%`）时，佣金会被算成
   销售额 × 18000% ⇒ 报出一个离谱的差额。先看「佣金率」列的单位。
3. **合计行没跟着更新**：改了明细行忘了改合计行，会同时报出"合计行与明细之和不符"。
   合计对不上时**先对齐行数**，再谈佣金率。
4. **跨期广告费**：广告费账单按整月投放、结算只算半个月时，差额是**期间错位**而不是平台多扣，
   别直接当成多扣去申诉。
5. **同一店铺多站点**：`店铺 + 平台 + 站点 + 期间` 才算一行；只按店铺去重会把
   不同站点的结算误判成重复结算。
6. **空缺列被当成 0**：某一行「其它费用」空着时，本工具**不**按 0 复算，而是报"关键字段缺失"。
   自己用 Excel 补 0 会把差额掩盖掉。

## 使用次数与完整档

本免费版每次运行结束后会向服务端做**一次匿名次数统计**：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），**不发送你的材料、不写任何文件**。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 统计不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**；
· 不想要这次统计可以加 `--no-stats`（核对功能完全不受影响，只是拿不到完整档说明）。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

## 这个工具会拦下什么（引擎原话）

1. 两张表口径要一致：先确认是不是账单期间与结算期间错开（跨期广告费最常在这里差）
2. 把这条差额和同一行里的三个扣项比一比（佣金 / 广告费 / 其它费用）：差额与哪一项相等
3. 要么明细行漏了某个店铺 / 平台 / 站点，要么合计行没跟着更新
4. 同一店铺 + 平台 + 站点 + 期间正常只有一行汇总；重复行会让佣金、广告费和净额一起翻倍
5. 缺这一格这笔钱就算不出来；补齐前本工具不会用 0 或默认值替你填，也不会替你下结论

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 跨店铺 / 跨平台 / 跨站点汇总台账（按维度合计销售额、佣金、广告费与净额）
- 按费用额从大到小排序的申诉清单（带行号、归因与应补 / 应退金额）
- 佣金率异常归因（超出 0~30% 合理区间 / 同一店铺同期间佣金率不一致 / 与整表口径系统性偏离）
- 广告费异常归因（广告费占销售额比例过高）
- 结算净额为负检测（扣项吃掉全部销售额）
- 费用项为负检测（佣金 / 广告费 / 其它费用出现负数）

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 边界（请务必知道）

本工具**不做**引擎 `CHECKS_OUT_OF_SCOPE` 里列的那些判断，特别是：

- 不判断平台佣金率档位、广告费单价**是否符合你和平台签的合同**（那是商务条款的事）；
- 不把广告费账单里的逐条投放明细（广告活动 / 关键词 / 素材）与结算单勾稽；
- 不核曝光 / 点击 / 转化等投放效果，也不判断广告花得值不值；
- 不处理汇率折算、退款与取消单、跨期结算、佣金返还等特殊口径；
- 不读 `.xlsx`，核对过程核对过程核对过程核对过程不联网抓平台后台的结算单或广告费账单（要你先导出成文本贴进来）；
- 不代你向平台申诉。

材料不足时**不给结论**，也不会输出「未发现问题」——
不会用 0 或默认值把缺失的格子补上再下结论。
