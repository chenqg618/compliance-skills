# 采购与付款技能包（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`scripts/engine/`）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**、**不写任何文件**。

## 什么时候用

**谁会在什么时候用**：采购、应付会计、财务共享中心与内控，在**月末结账、供应商对账、
付款审批、暂估清理、招标与合同付款**这些固定节点上。
采购与付款底稿从来不是一张表：供应商应付对账、应付账龄与付款计划、暂估入账与发票未到、
应付保理与贴现、采购返利与阶梯、投标保证金收退、履约保证金与保函台账、中标结果与合同一致性、
合同一致性、多份合同条款差异、三单匹配（订单/入库/发票）、报销单合规、预付卡消费核销、
预收账款与收入确认 —— 每一张都有自己的勾稽关系，
逐张手核既慢又容易漏，而且**月月都要重复一遍**；
**一笔对不上的应付、一个算错的暂估、一张没匹配上的发票，后果比多花半小时严重得多**。

**这个包做的事只有一件**：`--input <对象目录>`（每个子目录 = 一个对象 / 一套材料），
一次跑完所有对象，**每个对象一行结论**。

## 这个免费版查什么

下面 14 项，**每个对象都跑一遍**（检查项名字与引擎 `CHECKS_GIVEN` 逐条一致）：

1. 供应商应付对账
2. 应付账款账龄与付款计划核对
3. 应付暂估与发票未到核对
4. 应付账款保理与贴现核对
5. 采购返利与阶梯核算核对
6. 投标保证金收退核对
7. 履约保证金与保函台账核对
8. 中标结果与合同一致性核对
9. 合同一致性AI核对
10. 多份合同条款差异比对
11. 三单匹配AI核对
12. 报销单合规预检
13. 预付卡消费核销核对
14. 预收账款与收入确认核对

引擎里的 `CHECKS_WITHHELD`（本免费版**不执行**的项）会逐条打印出来，例如
「跨对象汇总台账」「采购付款风险排序清单」「跨对象共性问题归类」「采购付款台账导出」——
**它们是"未执行的检查项"的说明文本，不是实现**。

另外，每个成员检查包**自己**没做的子检查（`SUB_CHECKS_WITHHELD`，本包合计 78 项）也在结果里
`scope.sub_checks_not_run` 如实列出 —— 两个档位都没实现它们，不会因为「买了完整档」就让买家以为这些项被跑了。

## 怎么用

```bash
node scripts/run.mjs --sample                  # 单对象样例（内置）
node scripts/run.mjs --sample-batch            # 3 个对象的批量样例
node scripts/run.mjs --input 对象目录           # 批量：每个子目录 = 一个对象
node scripts/run.mjs --input 对象目录 --json    # 机器可读
```

对象目录怎么放（每个子目录里放该对象的一套采购与付款材料，每项用 `=== 检查项 ===` 分段，Tab 分隔最稳）：

```
对象目录/
  采购部-2026-05/采购付款材料.txt
  供应商对账组-2026-05/采购付款材料.txt
```

也可以把 14 张表拆成 14 个文件放进同一个子目录 —— 引擎按 `=== 检查项 ===` 的段标题找对应的那一项。
`templates/sample.json` 是引擎自己的样例，可以直接 `--input` 它先跑通一遍。

**退出码**：0 已执行检查 / 1 缺少入参 / 3 材料不足 / 4 入参读不到或无法解析 / 9 未预期错误。
**材料不足**（一个对象的材料都没有、材料为空或只有一两行、认不出任何一张表）时，
本工具**不做任何认定、也不给任何结论**，打印缺什么并以退出码 3 结束 —— 不会把"没查"说成"通过"。

## 结论怎么读

- 每个对象一行：`[结论] 对象名｜问题 N 项（P0/P1/P2）｜每一项:通过 / 有问题(n) / 未执行`；
- 有价值的是**问题明细**：每条都带 `对象 + 检查项 + 来源文件:行号 + 类别 + 具体数字`，
  第三方可以拿同一份材料复算；
- 行号一律**以你的原文内容为准落位**（成员引擎内部的行号口径不统一，本包只按"这一行在原文里真的存在"
  来定位），所以拿行号回原文一定找得到那一行。

## 常见错法

- **14 张表塞进一个文件却不写段标题**：引擎按 `=== 检查项 ===` 段标题把材料派给对应的检查项；
  没有段标题时只有能自己认出表头的那几项会跑，其余如实标「未执行」并报一条「材料只覆盖了一部分」，
  不是"查过了没问题"。
- **一个对象一个目录**：`--input` 指向的目录里，**每个子目录 = 一个对象**。
  把所有供应商 / 所有期间的底稿放进同一个子目录，会被当成**一个**对象，跨对象的差异与汇总也就无从谈起。
- **以为「未执行」=「通过」**：某对象只交了 3 张表，那 3 项之外的 11 项是**没有核**，
  结论里写的是「未执行」，并且会单独报一条覆盖缺口。
- **把合同全文与应付台账混在一段里**：合同一致性、三单匹配、报销单合规这三项是**自由文本型**检查，
  它们会拿整段文字去找线索；段标题写错会让它们去查别的检查项的材料（本包按段标题派发，就是为了避免这件事）。
- **拿 `--sample` 的输出当自己的结论**：样例只是让你确认「跑得通、格式对」，
  真正的结论必须来自你自己的材料。


## 使用次数与完整档

本免费版每次运行结束后会向服务端做**一次匿名次数统计**：只发送本包标识和一个不含任何材料的匿名安装标识（由主机名与用户名做短哈希得到），**不发送你的材料、不写任何文件**。

· 前 3 次：服务端不返回任何内容，输出与现在完全一样；
· 第 4 次起：服务端会返回一段**完整档说明**（完整档是另一个独立商品，条款与价格以它自己的商品页为准），届时才会打印这一行；
· 统计不可用（离线/超时/被拦截）时什么都不做，**核对结果与退出码不受任何影响**。

本版本不包含的检查项见上一节；需要完整档时按服务端返回的官方口令执行，付款由用户本人确认。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 跨对象汇总台账（全部对象 × 全部 14 项检查合并成一张总表）
- 采购付款风险排序清单（按 P0/P1/P2 排序，带对象名与原文文件行号）
- 跨对象共性问题归类（同一问题命中 2 个及以上对象时合并成一条共性项）
- 采购付款台账导出（Markdown 与 CSV 文本，直接用于付款审批附件与结账前复核说明）

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 边界（请务必知道）

- **不做**某笔采购、付款、保理、贴现、返利该不该做、金额该不该付的判断（属于业务与审批判断，
  请按合同、授信与审批结论执行）；
- **不核对**发票 / 合同 / 入库单 / 保函的真伪，也不查询供应商与客户的征信、失信名单；
- **不代替审计**，也不出具鉴证意见或审计意见；**不判断**适用税率、返利率、融资比例、保证金比例该取什么值；
- **不读取** ERP / 采购系统 / 报销系统 / 网银的导出文件 —— 需要你先导出成文本，每个对象一个目录。
