# 外卖平台抽佣与配送费核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`scripts/engine/`）。
> 不联网、不需要 API Key、**没有调用次数上限**；账单材料不出本机。

## 什么时候用

**谁会在什么时候用**：每一家做外卖的餐饮店（单店或连锁）在**每月拿到美团 / 饿了么 / 抖音外卖的账单之后、确认结算之前**，
都要把这张账单核一遍，才能确认这个月到底该收多少钱。

**这张账单会逐项核对什么**：
· 佣金（技术服务费）= 结算基数 × 佣金率
· 商家实收 = 结算基数 − 佣金 − 配送费商家承担 − 活动补贴商家承担
· 账单合计行逐列复核（每一列合计是否等于各明细行之和）
· 重复行检测（同一门店 + 同一平台 + 同一期间出现多行）
· 空白与占位符检测（关键字段缺失时不复算、也不套默认值）

每条结论都带**原文行号**，并在 `basis` 里原样引用那一行，可被第三方用同一份账单复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 输入格式

一行表头 + 若干明细行 + 一行合计行，Tab 分隔（从 Excel 或平台后台导出后直接复制）。
表头要能认出：门店 / 平台 / 期间 / 结算基数 / 佣金率 / 佣金 / 配送费商家承担 / 活动补贴商家承担 / 商家实收；
订单数是可选列。金额可以带千分位与百分号（`120,000.00`、`8%` 都认）。

## 常见错法（外卖对账里真的会有人这么填）

1. **把「配送费商家承担」填成配送费总额**：平台承担的那部分也被算到商家头上，商家实收必然对不上，而且往往是每月都在少收。
2. **佣金列与佣金率列互相矛盾**：佣金率写 8% 却按 12% 的金额填佣金（或者反过来，佣金列里填的是配送费列的金额）—— 复算一跑就露。
3. **同一门店同一平台拆成两行**：把"明细行 + 汇总行"一起贴进同一张表，佣金、配送费、实收会一起翻倍，合计行反而看起来是对的。
4. **活动补贴只填平台补贴、漏掉商家承担的满减分摊**：实收自己和自己算得平，但商家实际承担的补贴没进账，等于白送。
5. **合计行手工敲、明细行改了没改合计**：合计与明细相差多少就是漏行或多行的金额；合计对不上时先核对行数，别急着谈佣金率。
6. **期间写法混用**（`2026-03`、`2026-3`、`3月`、`3.1-3.31`）：同一期间的重复行会因为写法不同而漏检，建议统一成 `2026-03`。

本免费版**只执行上面那 5 项**；下面这些**本次没有执行**，也不会用默认值替你猜：

- 差异归因（把每笔差额归到：佣金档位错 / 配送费重复承担 / 活动补贴未结算）
- 补款金额与门店月度差额排序（追款清单，按门店合计差额从大到小）

- 费用项（佣金 / 配送费 / 活动补贴）为负检测

## 边界（请务必知道）

- 本工具**不判断**平台佣金率档位是否符合你与平台签的合同 —— 它只按**账单自己列示的**佣金率复算。
- 本工具**不把订单明细逐笔**与汇总行勾稽（本表是账单汇总口径）；要逐笔核，请先把订单明细汇总成同结构。
- 本工具**不处理**退款 / 取消单 / 跨期结算 / 佣金返还等特殊口径，也不处理配送费按距离、时段、天气计价的规则差异。
- 本工具**不联网**抓取平台账单，也不读 `.xlsx`：请先把账单导出成文本贴进来。
- 材料不足（认不出表头 / 没有明细行）时**不给结论**，也不会输出「未发现问题」。
